# ADR-0002 — مرجع واحد و ورودی مستقیم اسناد

**وضعیت: Approved برای سازمان‌دهی اسناد. تاریخ: ۲۰۲۶-۱۱-۰۲. مالک تصمیم: صاحب محصول.**

## مسئله و شواهد

مالک در جلسه نتوانست فناوری‌های پروژه را در مخزن اسناد پیدا کند و مجبور به جست‌وجو در مخزن کد شد. همچنین مخزن کد و مخزن اسناد هنوز تقدم مرجع یکسانی اعلام نمی‌کردند. [متن واقعی درخواست](../journal/2026-11-02/OWNER-AUTHORIZATION.raw.fa.md).

## گزینه‌ها

| گزینه | نتیجه |
|---|---|
| ادامهٔ لینک‌دادن به چند مخزن و README چندمرحله‌ای | رد برای ورودی اصلی؛ پاسخ سؤال معمول پیدا نمی‌شود |
| کپی فعال همهٔ قواعد در هر مخزن | رد؛ دو نسخهٔ مستقل از قانون ایجاد می‌شود |
| مخزن معماری به‌عنوان مرجع موضوعی، با پاسخ مستقیم و نسخهٔ ثابت شواهد | انتخاب شد |

## تصمیم و دامنه

محصول، فناوری، وضعیت، طراحی ماژول، تصمیم و قرارداد مستند در sfp24-architecture خوانده شوند. کد، migration قابل اجرا، تست و راه‌انداز در مخزن محصول بمانند. راهنمای متنی اجرا در مخزن معماری با نسخهٔ مبناست؛ ورودی قدیمی مخزن کد فقط به همین مرجع هدایت کند. snapshotهای تاریخی بدون بازنویسی و با manifest نگه داشته شوند.

صفحهٔ اول باید پاسخ مستقیمِ محصول/فناوری/وضعیت داشته باشد. اسناد تفصیلی آموزش در مسیر موضوعی فعال قرار گیرند؛ نیازهای مشترک به مالک هسته لینک دهند. بحث اتاق/میز، SDK و Seat همچنان باز می‌ماند.

## پیامدها و بازنگری

ارجاع به کد ثابت و دامنهٔ شواهد اجباری است؛ خود متن، تست یا migration اجرا نمی‌کند. لینک‌های قدیمی با redirect/resolver حفظ می‌شوند. اگر خواننده برای یک سؤال معرفی هنوز مجبور به عبور از چند README شود، ورودی باید اصلاح شود. تغییر قرارداد فنی از این ADR نتیجه نمی‌شود.
