## نیاز یک ماژول به هسته

ابتدا [سند اصلی قواعد هسته](../core/README.md) را برای نیاز خود پیدا کنید. حساب و مجوز را برای هر ماژول از نو نسازید. منطق تخصصی محاسبه باید در ماژول مربوط باشد؛ ابزار نمایش، جای سرویس رسمی محاسبه نیست. [قواعد ارتباط بخش‌ها](../contracts/README.md).

## نویسندهٔ یک ماژول از کجا شروع می‌کند؟

1. [معرفی محصول](../PRODUCT.fa.md) و [وضعیت ساخت](../STATUS.fa.md) را بخوانید؛ نام ماژول به معنی آماده‌بودن آن نیست.
2. وارد README ماژول خود در جدول بالا شوید. در OEE یک [مسیر شروع مشخص](oee/README.md) نوشته شده است.
3. برای هویت، مجوز، داده و نمایش از [قواعد مشترک هسته](../core/README.md) استفاده کنید؛ نیازی به خواندن تاریخچهٔ همهٔ ماژول‌ها نیست.
4. هر نیازِ بدون پاسخ را با [قالب درخواست](../governance/CHANGE-WORKFLOW.md) پیگیری کنید. ماژول دیگر را از روی فرض، وابستگی اجباری نکنید.
5. اسناد و سوابق خود را در پوشهٔ همان ماژول و از مسیر RECORDS آن نگه دارید. برای ماژول جدید همین ساختار و راهنمای README را به کار ببرید: هدف، وضعیت، سناریو، ورودی/خروجی، ارتباط با هسته و دیگر ماژول‌ها، سؤال‌های باز، اسناد و سوابق. پوشهٔ جدید نیازمند محتوای واقعی است؛ صرف نام یک قابلیت ماژول آماده نمی‌سازد.
