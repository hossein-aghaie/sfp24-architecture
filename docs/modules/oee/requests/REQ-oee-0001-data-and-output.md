# REQ-oee-0001 — روشن‌کردن اتصال پارامتر و خروجی برای مصرف‌کنندهٔ مستقل

**تاریخ:** ۲۰۲۶-۱۱-۰۲ · **مبدأ:** سناریوی نویسندهٔ OEE در بازبینی اسناد · **مقصد:** هسته / داده و رابط · **وضعیت:** ثبت‌شده؛ تصمیم فنی و اجرای اتصال هنوز تأیید نشده.

این یک کمبود واقعیِ مستندات اتصال است، نه سفارش ساخت موتور OEE. در بازبینی [درخواست صاحب محصول](../../../journal/2026-11-02/DOCUMENTATION-READABILITY.fa.md) مطرح شد که نویسندهٔ OEE باید بداند پارامتر را از کجا بردارد و نتیجه را کجا وصل کند. [Q03 تا Q05 هسته](../../../core/OPEN-QUESTIONS.md) زمینهٔ قبلی همین نیازها هستند.

## نیاز

نویسندهٔ ماژول مستقل باید بداند برای یک شرکت و تجهیز مجاز، دادهٔ پارامتر را در بازهٔ مشخص از چه رابطی دریافت می‌کند؛ چه ویژگی‌های نوع/واحد/زمان/معنا و کیفیت قابل دسترسی‌اند؛ و نتیجهٔ محاسبه را چگونه برای گزارش و نمایش ارائه می‌کند. داشتن نام Tag یا پارامتر، این اتصال را به‌تنهایی تعریف نمی‌کند.

## چیزی که بررسی شد

[داده و پارامتر](../../../core/DATA-AND-PARAMETERS.fa.md)، [مصرف شمارش در تولید](../../../operations/guides/PRODUCTION-DATA-SOURCES.md)، [میزهای کار](../../../core/WORKSPACES.fa.md) و سه [پیش‌نویس ارتباطی](../../../contracts/README.md) خوانده شدند. آن‌ها مسیر مفهومی و یک مصرف موجود را نشان می‌دهند؛ مشخصات کامل API عمومی مصرف مستقل و انتشار خروجی OEE در این اسناد تعیین نشده است. این بازبینی، جست‌وجوی تازهٔ کد برای اثبات نبود هر سرویس داخلی نبوده است.

## پاسخ لازم از هسته

| سؤال | پاسخ فعلی در این درخواست |
|---|---|
| کدام رابط موجود، با چه نسخه و چه ورودی‌ای قابل استفاده است؟ | نیازمند بررسی نویسندهٔ هسته؛ API فرضی نام‌گذاری نشده |
| شرکت، تجهیز و مجوز خواندن چگونه کنترل می‌شوند؟ | قواعد کلی هویت موجود است؛ اتصال اختصاصی این مصرف باید ارجاع دقیق بگیرد |
| نبود داده، دادهٔ دیررس، پوشش ناقص بازه و نوع مقدار چگونه اعلام می‌شوند؟ | نیازمند تعیین قرارداد مصرف؛ صفر فرض نشود |
| نتیجهٔ محاسبه کجا ذخیره/ارائه و به گزارش یا ابزار نمایش وصل می‌شود؟ | تصمیم و قرارداد فنی لازم است؛ Widget موتور محاسبه فرض نمی‌شود |
| آیا تغییر هسته لازم است یا سرویس موجود کافی است؟ | بدون بررسی کد و نیاز سناریوی منتخب معلوم نیست |

## اثر و گزینه‌ها

هسته ابتدا می‌تواند رابط موجود را با نسخه و محدودیت مستند کند. اگر کافی نبود، اصلاح همان قرارداد بررسی می‌شود. ایجاد SDK یا bus عمومی، دسترسی مستقیم به جدول ماژول دیگر یا ساخت پارامتر موازی، نتیجهٔ خودکار این درخواست نیست. اثر بر مجوز، جداسازی شرکت‌ها، نسخه، ذخیرهٔ نتیجه و مصرف‌کنندگان موجود باید مشخص شود.

## تصمیم و نتیجه

هنوز تصمیم فنی، API مصوب، مجوز اجرای این اتصال، کامیت پیاده‌سازی یا آزمون اتصال ثبت نشده است. پاسخ تخصصی هسته و نتیجهٔ بررسی بعدی در همین فایل افزوده می‌شود. پس از تصمیم، فقط سند اصلی قرارداد اصلاح و از اینجا لینک می‌شود.
