# ثبت و گزارش تولید

اولین ماژول عملیاتی محصول برای گزارش کار انجام‌شده و مشاهدهٔ سوابق است. ورودی می‌تواند دستی یا شمارش معتبر دستگاه باشد؛ پلان پیش‌نیاز همهٔ ثبت‌ها نیست.

**وضعیت:** بخشی از جریان ثبت و گزارش تولید در پایلوت پیاده شده و در حال تکمیل و اعتبارسنجی است. [پروندهٔ فنی پایلوت](https://github.com/hossein-aghaie/pouyeshgar-workshop/blob/627feed3f93411554be0ed0be623ec43ec1e106b/docs/development/core-module-pilot-v1/README.md)

| موضوع | مرجع |
|---|---|
| چه ساخته شده و چه محدودیت دارد؟ | [وضعیت محصول](../../STATUS.fa.md) |
| ثبت کار و گزارش | [راهنمای عملیات](../../operations/guides/PHASE3B-OPERATIONS.md) |
| ورودی شمارش و پارامتر | [راهنمای منابع تولید](../../operations/guides/PRODUCTION-DATA-SOURCES.md) |
| Person/Account و مجوز خود/دیگران | [هویت](../../core/IDENTITY-AND-ACCESS.fa.md) |
| داده و مصرف رسمی | [پارامترها](../../core/DATA-AND-PARAMETERS.fa.md) |

شمارش دستگاه به‌تنهایی تولید سالم یا OP فرد را اثبات نمی‌کند. گزارش نهایی، Permission و منشأ خودش را دارد؛ ویجت نمایشی جای ثبت واقعی را نمی‌گیرد. OEE و برنامه‌ریزی موتور جدا می‌خواهند؛ از وجود این ماژول اجراشده فرض نشوند.

## ثبت و ادامهٔ کار این ماژول

[اتاق فکر و فهرست سوابق همین ماژول](RECORDS.md) نقطهٔ ورود ایده‌ها، گفتگوها، تحقیقات، آزمایش‌ها و درخواست‌هاست. اسناد تخصصی در همین پوشه باقی می‌مانند؛ قواعد مشترک هویت/پارامتر/مجوز فقط به [هسته](../../core/README.md) لینک می‌خورند.

برای نیاز از هسته یا ماژول دیگر، [روش و قالب درخواست](../../governance/CHANGE-WORKFLOW.md) را استفاده کنید و لینک آن را در [فهرست مشترک درخواست‌ها](../../governance/REQUESTS.md) ثبت کنید. وجود پوشه یا پیش‌نویس، اجازهٔ کدنویسی قابلیت جدید نیست.
