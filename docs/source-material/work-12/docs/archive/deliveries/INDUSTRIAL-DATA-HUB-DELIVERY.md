# تحویل مسیر اولیهٔ Industrial Data Hub — NEWAY

## سند تحویل تاریخی مسیر اول

این گزارش شواهد مرحلهٔ اول را حفظ می‌کند. محدودیت Preview-only و نبود REST/Excel مربوط به همان مرحله است؛ وضعیت فعلی در [راهنمای منابع تولید](../../guides/PRODUCTION-DATA-SOURCES.md) و گزارش تحویل جدید ثبت می‌شود. تصاویر قدیمی برای مقایسهٔ قبل/بعد حفظ شده‌اند.

این توسعه روی `feat/industrial-data-hub-neway` و در Worktree مستقل `.local/worktrees/industrial-data-hub` انجام شد. مبدأ `61cd56a` روی `feat/unify-phase2-tenant-shell` بود؛ آخرین تغییرات قبلی از قبل Commit و Push شده بودند. به Branchهای قبلی Merge، Deploy یا Stash قدیمی دست زده نشد. فایل‌های محلی طراحی در Checkout اصلی دست‌نخورده ماندند.

## قابلیت قابل استفاده

در همان Factory، صفحهٔ «منابع و اتصالات داده» اضافه شده است: ایجاد و غیرفعال‌کردن اتصال HTTP، کلید اختصاصی یک‌بارنمایش/قابل چرخش، انتساب زمان‌دار Node به تجهیز، Binding ورودی تولید، مشاهدهٔ شمارش دقیقه‌ای و منشأ پیام، پوشش/صفر/دیررس/گپ/تعارض و انتخاب بازهٔ واقعی. دکمهٔ «بازهٔ داده‌های موجود» آخرین پوشش ذخیره‌شده را تا سقف هفت روز انتخاب می‌کند؛ برای مرور آزمایش دیروز لازم نیست زمان را حدس بزنید.

مهاجرت افزایشی ۶ شامل جدول مرکزی `data_hub_keys` و هفت جدول شرکتی `hub_connections`, `hub_assignments`, `hub_bindings`, `hub_raw_events`, `hub_measurements`, `hub_conflicts`, `hub_ingestion_receipts` است. سرویس و API مستقل از Production است؛ API نسخه‌دار، مجوز سمت سرور، جداسازی شرکت‌ها و کلید دستگاه مستقل از نشست کاربر دارد. فهرست قراردادها و محدودیت‌ها در [راهنمای فنی](../telemetry-v1/INDUSTRIAL-DATA-HUB.md) آمده است.

APIها: دریافت `POST /api/v1/data-hub/ingest/http` و مسیر `.../replay` فقط برای SIMULATOR؛ تنظیمات و خواندن زیر `/api/v1/company/data-hub`؛ اتصال‌ها `connections`، انتساب `connections/:id/assignments`، کلید `connections/:id/key`، Bindingها `bindings`، خواندن `connections/:id/measurements`، منشأ `raw/:id` و پیش‌نمایش مصرف‌کننده `production-count`.

## بررسی روی همین لپ‌تاپ

- محیط تازه: `http://127.0.0.1:5196/company/neway-review/login`، API روی `127.0.0.1:5197`.
- ریشهٔ همین Web از شبیه‌ساز مستقلِ حافظه‌ای روی۵۱۹۸ استفاده می‌کند؛ درخواست‌های Demo این شاخه به API یا فایل دادهٔ پایلوت قبلی فرستاده نمی‌شوند. عنوان/نوار وضعیت Data Hub منبع HTTP و بازهٔ اختصاصی صفحه را نشان می‌دهد؛ برچسب عمومی MANUAL و بازهٔ نامرتبط داشبورد برای این صفحه نمایش داده نمی‌شود.
- نام شرکت کاملاً فرضی است. این محیط با دیتابیس مرکزی/شرکتی جدید روی MariaDB آزمایشیِ از قبل مجازشدهٔ `127.0.0.1:3317` کار می‌کند. هیچ Migration یا انتقال داده‌ای روی دیتابیس شرکت قبلی اجرا نشد. نسخهٔ قبلی روی۵۱۷۶ جدا باقی مانده است.
- ورود خصوصی در `.local/worktrees/industrial-data-hub/.local/data-hub/private/REVIEW.json`، نسبت به Checkout اصلی قرار دارد. رمز/کلید در Git یا این سند درج نشده است. دسترسی فایل‌های خصوصی فقط برای مالک فعلی Windows، SYSTEM و Administrators محدود شده است.
- پس از ورود، «منابع و اتصالات داده» → «بازهٔ داده‌های موجود» را بزنید. اتصال SIMULATOR دارای ۶ دقیقه با مجموع۱۲۳ و یک صفر صریح است. در پیش‌نمایش ضایعات۳ وارد کنید؛ سالم۱۲۰ می‌شود. یک Binding معتبر و فعال برای این تجهیز وجود دارد. این محاسبه گزارش تولید ذخیره نمی‌کند.
- ابزار ارسال ساختگی `scripts/send-hub-demo.mjs` فقط Loopback را می‌پذیرد. نمونهٔ دقیق و کلید آزمایش خصوصی در همان پوشهٔ `private` با نام‌های `review-packet.json` و `review-key.json` است. دستور اجرای آن در راهنمای فنی آمده؛ تکرار همان بسته نباید شمارش را افزایش دهد.
- Start/Stop محلی همین نمونه در `.local/worktrees/industrial-data-hub/.local/data-hub/Start.cmd` و `Stop.cmd` است. تست توقف/شروع مجدد موفق شد؛ فقط Web/API همین نمونه را با کنترل PID و زمان ایجاد متوقف می‌کنند. MariaDB و سرویس‌های قبلی را متوقف نمی‌کنند. این اسکریپت‌های وابسته به لپ‌تاپ، داده‌ها و فایل‌های خصوصی در Git نیستند.

## شواهد اجرا

- کل تست‌های فعلی و جدید با MariaDB واقعی: **۹۰ موفق، صفر شکست، صفر Skip**. شامل Migration تکرارشونده، ظرفیت/رمز/مجوزهای قبلی، دو شرکت فرضی، کلید اشتباه، Node اشتباه، زمان/شمارش نامعتبر، حفظ داده در نمونهٔ تازهٔ API، ممنوعیت UPDATE/DELETE دادهٔ خام، انتقال تجهیز، غیرفعال‌سازی، مجوز ماژول و رقابت هم‌زمان Binding/Retry.
- TypeScript و Build تولید موفق. هیچ Dependency جدیدی نصب نشده است.
- Playwright با Chrome واقعی: ورود، ساخت اتصال و کلید، ارسال واقعی HTTP، ناقص۸۳ → دریافت دیررس۴۰ →۱۲۳، شش Retry بدون افزایش، صفر در برابر فقدان داده، منشأ خام، Preview۳→۱۲۰، ساخت/غیرفعال‌کردن Binding، تغییر بازه به سه دقیقه و مجموع۹۳، تعارض۴۰/۴۱ و مجموع معتبر۵۳ همراه با غیرفعال‌شدن Preview؛ فارسی RTL/انگلیسی LTR و موبایل.
- دسکتاپ۱۳۶۶×۷۶۸: `scrollHeight=clientHeight=768`؛ دسکتاپ۱۹۲۰×۱۰۸۰: هر دو۱۰۸۰. جدول داخل Workspace اندازه‌گیری شد و پشت Overflow پنهان نیست؛ اسکرول داخلی دارد. موبایل۳۹۰×۸۴۴ اسکرول طبیعی دارد، بدون Overflow افقی.
- رگرسیون مستقل و بدون نوشتن در دادهٔ مالک: Immersive/Explore/Analytics در هر دو اندازه، Three.js واقعی، انتخاب Raycasting و زوم با چرخ ماوس موفق.
- تصاویر و JSON نتیجهٔ محلی در `.local/worktrees/industrial-data-hub/.local/qa/data-hub/` هستند؛ شامل `fa-1366.png`, `fa-1920.png`, `fa-mobile.png`, `en-1366.png`, `raw-provenance.png`, `settings-binding.png`, `conflict.png`, `result.json` و زیردایرکتوری `pilot-regression`. تصویر کلید یا رمز منتشر نشده است. ابزار تکرار مرورگر: `scripts/data-hub-qa.mjs` با Opt-in محیط ساختگی؛ به Login خصوصی Fixture، Playwright و Chrome محلی نیاز دارد.

## مرزهای تحویل

این نسخه اولین مسیر عملیاتی **آزمایشی** است. پروتکل/کلید/ساعت واقعی Firmware بررسی نشده، هیچ EdgeBox یا سرویس واقعی فراخوانی نشده و آمادگی بهره‌برداری واقعی ادعا نمی‌شود. HTTPS و محدودسازی شبکهٔ نصب واقعی باید قبل از اتصال بیرونی بررسی شوند.

ProductionEditor دستی حفظ شده است. API مصرف‌کننده و انتساب ورودی کار می‌کنند اما ذخیرهٔ گزارش خودکار، قفل مصرف بازه، Snapshot دائمی شواهد و انتساب قطعه/OP ساخته نشده‌اند. شمارش دستگاه با گزارش دستی جمع نمی‌شود و گزارش نهایی قبلی با رسیدن دادهٔ دیررس تغییر نمی‌کند. تعارض‌ها خودکار حل نمی‌شوند. سیاست نگه‌داری/پاک‌سازی داده، مانیتور چندنمونه‌ای و منبع پیش‌بینی نساخته‌ایم.

تب چهارم Custom Dashboard و Grafana اضافه نشده‌اند. برای Grafana، MQTT، OPC UA، SCADA، RFID و سایر اتصال‌های آینده فقط قرارداد کوتاه توسعه در راهنمای فنی آمده است؛ هیچ کنترل تزئینی یا ادعای انطباق استاندارد اضافه نشده است. نتیجهٔ CI باید برای SHA نهایی Push‌شده در Actions بررسی شود؛ گزارش تحویل چت لینک همان اجراها را ارائه می‌کند.
