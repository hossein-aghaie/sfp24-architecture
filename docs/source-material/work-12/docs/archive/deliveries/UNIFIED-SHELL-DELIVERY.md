## نتیجهٔ قابل استفاده

ورود شرکت اکنون خود `src/App.vue` را باز می‌کند: منوی کناری، Three.js واقعی، Immersive / Explore / Analytics، انتخاب تجهیز، لایه‌ها، دوربین، نمایشگر و Device Detail. نام شرکت و کاربر و منبع دستی در پوسته دیده می‌شوند. فرم‌های موجود اطلاعات پایه، کاربران/مجوزها، ثبت چندردیفی، پیش‌نویس/نهایی‌سازی/اصلاح و CSV قطعات در همان منوها استفاده می‌شوند؛ حساب شرکت خانهٔ موازی ندارد.

شرکت خالی همان محیط را همراه راهنمای شروع می‌بیند؛ ۱۶ دستگاه یا آمار Demo خودکار دریافت نمی‌کند. تعریف کارخانه/سالن/منبع از اطلاعات پایه و تعیین شکل، ابعاد و موقعیت از چیدمان انجام می‌شود. شناسهٔ آبجکت همان شناسهٔ منبع عملیاتی است. موقعیت در MariaDB اختصاصی شرکت با نسخه و سابقه ذخیره می‌شود؛ تغییر هم‌زمان نسخهٔ قدیمی رد می‌شود. ویرایش هندسهٔ کامل فعلاً نیازمند مدیریت اطلاعات پایه در کل شرکت و نداشتن منع دامنه‌ای است؛ خواندن برای کاربران محدود فیلتر می‌شود.

آمار دستی همان API و جداول قبلی را مصرف می‌کند. سالم، ضایعات، روند روزانه و گروه‌های تجهیز/قطعه/OP/واحد در همان نماها دیده می‌شوند؛ چند OP یا واحد نامرتبط با هم به‌عنوان محصول نهایی جمع نمی‌شوند. OEE/A/P/Q، زمان کار، وضعیت لحظه‌ای، Edge و برنامهٔ تولید بدون ورودی معتبر ساخته نمی‌شوند. گیج‌های اصلی با وضعیت دادهٔ ناکافی و توضیح اختصاصی حفظ شده‌اند.

بازه‌های روزانه/هفتگی/ماهانه بر تاریخ گزارش‌اند. بازهٔ ساعتی، دلخواه و شیفت فقط گزارش‌هایی را محاسبه می‌کند که **تمام بازهٔ ثبت‌شده‌شان** داخل انتخاب باشد؛ تعدادها میان ساعت‌ها تقسیم فرضی نمی‌شوند. فیلتر مکان، تجهیز منتخب، قطعه و OP به API مشترک اعمال می‌شود. نمودار روزانه به نرخ یا تله‌متری تبدیل نشده است.

تصاویر و نتیجهٔ خام عمداً در Git نیستند: `.local/qa/unified-shell/` و `.local/qa/phase3b/pilot-regression/`. مقایسهٔ شش تصویر Before/After در `.local/qa/unified-shell/comparison.html` است. ## تست دستی شما

1. [ورود پویشگر آزمایشی](http://127.0.0.1:5176/company/pouyeshgar-test/login) با همان نام کاربری و رمز فعلی خودتان؛ رمز شما تغییر نکرده و در تست‌ها استفاده نشده است.
2. در همان محیط پایش، «اطلاعات پایه» → کارخانه، سالن و تجهیز را تعریف کنید؛ قطعه، OP و شیفت از همان‌جا قابل دسترسی‌اند.
3. «چیدمان کارگاه» → سالن را به صحنه اضافه کنید، تجهیز و شکل نمایشی را انتخاب و ابعاد/موقعیت را بررسی کنید، سپس «ذخیرهٔ جانمایی شرکت». ابعاد اولیه پیشنهادی‌اند؛ اندازه‌برداری واقعی محسوب نمی‌شوند.
4. «تولید و عملیات» → ثبت تولید سالم/ضایعات → ثبت نهایی. به پایش برگردید، همان تجهیز و بازهٔ گزارش را انتخاب کنید و سه نما و Detail را بررسی کنید.

ورود/خروج JSON جانمایی با پیش‌نمایش و شناسه‌های همین شرکت است. فایل قدیمی فاز ۲ یا شرکت دیگر خودکار رکورد عملیاتی نمی‌سازد؛ برای استفادهٔ مجدد باید هویت‌های واقعی با دادهٔ همین شرکت تطبیق داده شوند. در این مأموریت آمار یا دارایی‌های پایلوت قدیمی به پویشگر آزمایشی منتقل نشده‌اند.

محیط لپ‌تاپ: وب 5176، API 5186 و Portable MariaDB روی 127.0.0.1:3317. از دیتابیس مرکزی و پنج دیتابیس آزمایشی موجود پشتیبان خصوصی گرفته شد و tenant v5 اعمال شد؛ فقط API و Worker ثبت‌شدهٔ همین محیط بازراه‌اندازی شدند. سرویس MariaDB و وب و محیط‌های دیگر تغییر پیکربندی نکردند.

## محدودیت‌های صریح

اتصال واقعی دستگاه/Edge، ERP، توقفات/تعمیرات/کیفیت عملیاتی شرکت و برنامه‌ریزی هنوز متصل یا ساخته نشده‌اند؛ ماژول مجاز ولی ناتمام وضعیت صادقانه دارد. Demo فاز ۲ جدا و محفوظ است. مدل‌ها ساده و قابل پیکربندی‌اند؛ فایل دقیق CAD/GLB سازنده اضافه نشده است. ویرایش دامنه‌ای بخشی از یک سند هندسه، نگاشت تعاملی خودکار فایل قدیمی به تجهیزات جدید، داشبوردساز و XLSX جزو این تحویل نیستند.
