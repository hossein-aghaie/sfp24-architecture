# راهنمای نصب، روشن و خاموش‌کردن هاب

این راهنما برای نسخهٔ محلی ویندوز است. هاب به برنامهٔ اصلی یا دیتابیس آن وصل نیست. Docker، WSL و دسترسی Administrator لازم نیست. همهٔ پورت‌ها فقط روی localhost باز می‌شوند.

## روی همین رایانه

از PowerShell وارد پوشه شوید و اجرا کنید:

```powershell
cd D:\git\pouyeshgar-industrial-platform
.\Start.cmd
```

این دستور دو فرایند مستقل را در پس‌زمینه اجرا می‌کند:

| بخش | آدرس | کاربرد |
| --- | --- | --- |
| پنل و API هاب | http://127.0.0.1:5220 | مدیریت شرکت‌ها، دستگاه‌ها، منابع و تحویل داده |
| MQTT هاب | mqtt://127.0.0.1:5221 | اتصال عامل دستگاه با کلید مخصوص خودش |
| پنل شبیه‌ساز | http://127.0.0.1:5223 | شبیه‌سازی ۵۰ دستگاه مستقل |

اطلاعات ورود مدیر در فایل `private/access.json` قرار دارد. فقط خودتان این فایل را باز کنید و ایمیل و گذرواژه را در پنل وارد کنید؛ فایل را در Git، پیام یا تصویر منتشر نکنید. در اولین اجرا یک حساب مدیر و ۵ شرکت نمونه با ۱۰ دستگاه برای هر کدام ساخته می‌شود؛ اجراهای بعدی داده‌ها را بازنشانی نمی‌کنند.

اجرای شبیه‌ساز به معنی شروع ارسال داده نیست: در صفحهٔ شبیه‌ساز **Start all agents** را بزنید. برای توقف موقت ارسال، **Stop agents** را بزنید؛ در این حالت خود سرورها همچنان روشن می‌مانند.

## خاموش‌کردن هر دو سرور

```powershell
cd D:\git\pouyeshgar-industrial-platform
.\Stop.cmd
```

این دستور فقط PIDهای ثبت‌شده در `private/processes.json` را بررسی می‌کند و پس از تطبیق مسیر اجرای همین پروژه، شبیه‌ساز و هاب را متوقف می‌کند. برنامه‌های دیگر، Ubuntu، Docker و سرویس‌های برنامهٔ اصلی را متوقف نمی‌کند. داده‌های ثبت‌شده و اطلاعات ورود حذف نمی‌شوند.

در ویندوز این توقف با پایان‌دادن به فرایند انجام می‌شود. برای توقف کم‌ریسک‌تر، ابتدا در شبیه‌ساز **Stop agents** را بزنید و صبر کنید بسته‌های در حال ارسال تمام شوند. SQLite با WAL برای بازیابی ثبت‌های commitشده تنظیم شده، اما بستهٔ در حال پرواز ممکن است پس از اجرای دوباره نیاز به ارسال مجدد داشته باشد؛ ادعای تحویل دقیقاً یک‌بار نداریم.

بستن صفحهٔ مرورگر، سرورها را خاموش نمی‌کند. بستن PowerShellی که Start را اجرا کرده نیز فرایندهای پس‌زمینه را متوقف نمی‌کند. سرویس ویندوز یا اجرای خودکار هنگام روشن‌شدن ویندوز نصب نشده است؛ پس از ری‌استارت رایانه دوباره Start را اجرا کنید.

## پس از تغییر کد یا دریافت نسخهٔ تازه

```powershell
.\Stop.cmd
git pull --ff-only
.\Start.cmd -Build
```

اگر `package.json` یا `pnpm-lock.yaml` تغییر کرده، پس از pull و پیش از Start نصب وابستگی‌های بخش بعد را هم تکرار کنید. اسکریپت Start داده‌ها را پاک نمی‌کند. تغییر ناسازگار ساختار دیتابیس در نسخه‌های آینده به راهنمای مهاجرت جداگانه نیاز دارد.

## نصب روی رایانهٔ ویندوزی دیگر

پیش‌نیازها: Git، PowerShell 7 (`pwsh`)، Node.js نسخهٔ 24 یا بالاتر و pnpm نسخهٔ 11.25.0. در این رایانه Node موجود محیط Codex هم به‌عنوان گزینهٔ جایگزین شناسایی می‌شود؛ روی رایانهٔ دیگر به آن وابسته نباشید. Node آزمایش‌شده 24.19.0 است.

مخزن خصوصی است؛ حساب GitHub شما باید اجازهٔ خواندن آن را داشته باشد. ابزار Git موجود یا GitHub Desktop را برای احراز هویت به‌کار ببرید؛ GitHub CLI اجباری نیست.

```powershell
git clone https://github.com/hossein-aghaie/pouyeshgar-industrial-platform.git
cd pouyeshgar-industrial-platform
pnpm install --frozen-lockfile --store-dir private/pnpm-store --config.cache-dir=private/pnpm-cache --config.state-dir=private/pnpm-state
.\Start.cmd -Build
```

مخزن شامل رمزها، دیتابیس، کلیدهای دستگاه، پروفایل محرمانهٔ شبیه‌ساز، node_modules و خروجی build نیست. وابستگی‌ها هنگام نصب دریافت و داده‌های نمونه و رمز مدیر هنگام اولین اجرا ساخته می‌شوند. پس از نصب روی رایانهٔ جدید، گذرواژه همان گذرواژهٔ رایانهٔ قبلی نیست.

## بررسی خطا

| اتفاق | اقدام |
| --- | --- |
| `pwsh` شناخته نمی‌شود | PowerShell 7 باید در PATH باشد؛ دستور جایگزین پایین هم به آن نیاز دارد. |
| Node.js 24 پیدا نمی‌شود | Node 24+ را آماده کنید؛ اسکریپت نسخهٔ قدیمی‌تر را جایگزین یا حذف نمی‌کند. |
| وابستگی یا فایل build پیدا نمی‌شود | دستور نصب بالا را اجرا کنید؛ سپس `Start.cmd -Build`. |
| پورت ۵۲۲۰، ۵۲۲۱ یا ۵۲۲۳ اشغال است | Start متوقف می‌شود و چیزی را نمی‌بندد. اگر همین هاب روشن است، از URL استفاده کنید یا اول Stop بزنید؛ برنامهٔ ناشناس را متوقف نکنید. |
| Start نیمه‌کاره شکست خورد | لاگ را بخوانید، سپس Stop را برای فرایندهای ثبت‌شدهٔ همین پروژه اجرا کنید. |
| Stop می‌گوید PID با پروژه تطبیق ندارد | حفاظت در برابر توقف برنامهٔ دیگر است؛ از فرمان عمومی kill یا توقف همهٔ nodeها استفاده نکنید. |
| صفحه باز است ولی داده نمی‌آید | وضعیت شبیه‌ساز، Enabled دستگاه، و خطای عامل را بررسی کنید؛ پنل دستگاه‌ها در شروع بدون داده است. |
| اتصال بیرونی رد می‌شود | فقط منبع و مقصد مصنوعی محلی مجازند؛ برای اتصال واقعی باید آدرس مشخص صریحاً مجاز و قراردادش بررسی شود. |

لاگ‌ها: `private/logs/hub.log`، `hub-error.log`، `simulator.log` و `simulator-error.log`. لاگ‌ها ممکن است اطلاعات عملیاتی داشته باشند؛ پیش از اشتراک‌گذاری بررسی و پاکسازی شوند.

اگر فایل‌های cmd را استفاده نمی‌کنید، معادل مستقیم آن‌ها:

```powershell
pwsh -NoProfile -File .\scripts\Start-Lab.ps1
pwsh -NoProfile -File .\scripts\Stop-Lab.ps1
```

## نگهداری داده و محدودیت‌ها

دادهٔ هاب: `private/hub.db` و در زمان اجرا فایل‌های WAL/SHM؛ کلید رمزگذاری اتصال‌ها: `private/master.key`؛ وضعیت شبیه‌ساز: `private/simulator/`. پوشهٔ private را پاک نکنید. برای پشتیبان‌گیری فایل‌محور، ابتدا هر دو فرایند را متوقف کنید و دیتابیس و کلید را امن و با هم حفظ کنید؛ کپی‌کردن فقط فایل db در زمان اجرای سرور پشتیبان کامل محسوب نمی‌شود.

اجرای لینوکس هنوز آزمایش نشده است. اسکریپت‌های Start/Stop این راهنما مخصوص ویندوزند. این نسخهٔ محلی جایگزین تنظیم سرویس لینوکس، TLS، پشتیبان‌گیری، مدیریت رمز و تست ظرفیت در استقرار عملیاتی نیست. جزئیات: [معماری](ARCHITECTURE.md)، [API](API.md)، [نتایج آزمون](VALIDATION.md) و [مجوزها](LICENSING.md).
