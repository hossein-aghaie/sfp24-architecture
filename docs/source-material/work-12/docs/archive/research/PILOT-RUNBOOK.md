## اجرا در Windows

Node.js >=22.12 و pnpm موجود را استفاده کنید؛ همهٔ خروجی‌ها زیر پروژه روی D نگهداری می‌شوند:

```powershell
Set-Location D:\git\pouyeshgar-workshop
$env:TEMP = "$PWD\.local\tmp"
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Force $env:TEMP | Out-Null
pnpm install --frozen-lockfile --store-dir "$PWD\.local\pnpm-store"
./scripts/dev.ps1 api
```

در ترمینال دوم `./scripts/dev.ps1 dev` و در ترمینال سوم `./scripts/dev.ps1 simulate` را اجرا کنید. آدرس رابط `http://127.0.0.1:5174/` و API `http://127.0.0.1:5184/` است. هر دو فقط روی loopback گوش می‌دهند. Vite درخواست `/api` را به API هدایت می‌کند؛ این پروکسی مربوط به توسعه است. `dist` به‌تنهایی API را اجرا نمی‌کند.

اسکریپت `dev.ps1` مسیر فایل‌های موقت و کش را داخل پروژه تنظیم می‌کند؛ برای اجرای مستقیم pnpm نیز متغیرهای TEMP/TMP/XDG را در همان ترمینال تنظیم کنید. کش تبدیل tsx در اسکریپت‌های Node خاموش است.

`pnpm simulate --watch` هر دقیقه دادهٔ صریحاً شبیه‌سازی‌شده ثبت می‌کند. اجرای بدون `--watch` یک نوبت است؛ در اولین نوبت حداکثر ۱۲ دقیقه برای هر تجهیز ثبت می‌شود. نوبت‌های بعد از آخرین رخداد ادامه می‌یابند؛ فاصله‌های طولانی بیش از ۱۲ دقیقه پُر نمی‌شوند. هیچ کیفیت/رخداد واقعی دستگاه از این داده استنتاج نشود.

در «تنظیمات پایلوت» وارد شوید. حساب‌ها و رمزهای تصادفی محلی در `.local/pilot-login.json` ساخته می‌شوند؛ فایل را خصوصی نگه دارید و به Git ارسال نکنید. حساب `pilot-admin` تنظیمات را تغییر می‌دهد، `pilot-viewer` فقط تجهیز `neway` را می‌بیند و `pilot-edge` فقط دسترسی ingest دارد. سپس منبع هدر را «API شبیه‌ساز» انتخاب کنید. ورود برای دادهٔ نمونهٔ محلی ضروری نیست. توکن فقط در حافظهٔ صفحه نگهداری می‌شود و با بارگذاری مجدد نیاز به ورود دوباره است.

احراز هویت محلی و مجوزهای API آزمایش شده‌اند؛ این پیاده‌سازی سامانهٔ هویت آمادهٔ بهره‌برداری عمومی نیست: مدیریت کاربران/نقش‌ها در UI، IAM، بازیابی رمز، ممیزی دسترسی، HTTPS و چرخهٔ استقرار امن نیاز به تکمیل دارند. جابه‌جایی نقش با پارامتر دلخواه مرورگر مجاز نیست؛ حساب و دامنه از تنظیمات خصوصی سرور می‌آیند. دسترسی تجهیزات در API فیلتر می‌شود. نام‌ها/هندسهٔ چیدمان محلیِ خود مرورگر دادهٔ عمومی API محسوب نمی‌شوند.

## ذخیره‌سازی و MariaDB

پیش‌فرضِ اجرا `.local/pilot-state.json` است؛ تنظیمات و تاریخچه با نوشتن سریالی و جایگزینی فایل ثبت می‌شوند و پس از restart باقی می‌مانند. این فایل برای آزمایش محلی و یک فرآیند API است؛ نگهداری بلندمدت، حجم زیاد، نویسندگان هم‌زمان و بکاپ عملیاتی نیازمند پایگاه داده‌اند.

آداپتور واقعی MariaDB با connector رسمی، کوئری پارامتری و تراکنش/قفل سطر پیاده شده است. هیچ دیتابیس، حساب یا سرویس موجود به‌صورت خودکار ایجاد/تغییر نمی‌شود. پس از تهیهٔ **دیتابیس و کاربر مستقل** توسط مالک، در محیط همان ترمینال:

```powershell
$env:DB_HOST = '127.0.0.1'
$env:DB_PORT = '3306'
$env:DB_NAME = 'pouyeshgar_pilot'
$env:DB_USER = 'pilot_user'
# DB_PASSWORD را در محیط خصوصی تنظیم کنید؛ فایل .env واقعی commit نشود.
pnpm db:migrate
$env:PILOT_STORAGE = 'mariadb'
pnpm api
```

Migration جدول `pilot_state` با InnoDB و payload دارای اعتبار JSON ایجاد و دادهٔ پایه را seed می‌کند؛ دادهٔ فایل محلی را خودکار منتقل نمی‌کند. این طرح سندمحور با قفل تراکنشی برای پایلوت است؛ جدول‌های نرمال‌شدهٔ تاریخچه، ایندکس‌های زمانی، retention و migrationهای تکاملی مرحلهٔ بعدند. خطای اتصال DB باعث توقف startup می‌شود، نه fallback پنهان به فایل. **در این محیط MariaDB اجرا نشده؛ صحت SQL، migration و مسیر ذخیره‌سازی آن با یک سرور واقعی هنوز تأیید نشده است.** فعال‌سازی آن را آمادهٔ بهره‌برداری اعلام نمی‌کنیم.

## قرارداد داده و محاسبات

`POST /api/ingest` نیاز به نقش ingest و دامنهٔ تجهیز دارد. قرارداد در `src/pilot/domain.ts` و نمونه در `server/fixture.ts` است: `version`, `id`, `nodeId`, `equipmentId`, `source`, `quality`, `intervalStart`, `eventTime`, `state`, `plannedSeconds`, `runSeconds`, `total`, `good`, `idealCycleSeconds`. سرور `receivedTime` را می‌سازد. زمان باید timezone داشته باشد. شمارنده‌های هر پیام **دلتا در همان بازه** هستند، نه شمارندهٔ تجمعی PLC.

شناسهٔ تکراری با محتوای یکسان پذیرفته و deduplicate می‌شود؛ محتوای متفاوت، بازهٔ هم‌پوشان، شمارش نامعتبر، زمان آینده یا تجهیز/Node بدون نگاشت رد می‌شود. firmware واقعی معلوم نیست؛ `source=edge` با خطای صریح not configured رد می‌شود. MQTT، نگاشت channel/raw PLC و ERP پیاده نشده‌اند. این قرارداد داخلیِ آداپتور نمونه است؛ سازگاری با Edge Box واقعی ادعا نشده.

گزارش `/api/events?start=...&end=...` فیلتر UTC و دامنهٔ سرور دارد. فقط بازه‌های کامل دارای quality=good در KPI منظور می‌شوند؛ رکوردهای ناقص در مرز بازه شمرده و از محاسبه کنار گذاشته می‌شوند. مخرج صفر و performance بیش از یک، OEE معتبر تولید نمی‌کند. مجموع شمارش عملیات، محصول نهایی نیست. هیچ OEE سالن یا میانگین OEE ماشین‌ها ساخته نشده.

تعریف KPI نام، فرمول امن از چهار قالب، نسخه، واحد ratio، دامنه equipment و aggregation=none دارد. قالب فرمول دلخواه اجرایی پذیرفته نمی‌شود. خروجی هر تجهیز شامل تعریف‌های پیکربندی‌شده و مقدار آنهاست؛ افزایش نسخه برای تغییر لازم است. این نسخه تاریخچهٔ کامل تعریف‌های قبلی یا بازتولید snapshot با تعریف زمان رخداد ندارد.

تقویم API چند شیفت، روزهای هفته، عبور از نیمه‌شب و تاریخ تعطیل را می‌پذیرد؛ در منبع API، «ابتدای شیفت تا الان» از همین تقویم استفاده می‌کند. تاریخ استثنا مربوط به روز شروع شیفت است. استثنای جایگزینی ساعت، تعیین تیم/کارکنان هر شیفت و حل هم‌پوشانی تقویم‌ها هنوز کامل نشده‌اند. ترتیب رکوردها در انتخاب اولین شیفت فعال اهمیت دارد؛ شیفت‌های هم‌پوشان برای بهره‌برداری تعریف نکنید. تنظیم زمان نسخهٔ پایه مستقل و یک‌شیفتی باقی مانده است.

## رابط و مرزهای محصول

Immersive و Explore همان نمونهٔ SceneView و raycaster را مصرف می‌کنند؛ Analytics جدول/روند/پارتو است. جزئیات یک فضای جداست و بازگشت انتخاب/بازه را حفظ می‌کند. نقشهٔ دوبعدی، ترجیحات لایه/برچسب، preset و حالت نمایشگر موجودند. با خاموش‌کردن برچسب‌ها، انتخاب مدل با raycast همچنان برقرار است. تراکم متعادل برای جلوگیری از پوشاندن مدل‌ها بعضی برچسب‌های مجاور را پنهان می‌کند؛ تجهیز حذف نمی‌شود.

ویرایشگر چیدمانِ `next` در `src/LegacyWorkspace.vue` حفظ شده و در تنظیمات تعبیه شده است. مسیر `/?baseline=1` نسخهٔ کامل پایه را برای regression QA باز می‌کند. ذخیرهٔ هندسهٔ محلی با کاتالوگ عملیاتی API مستقل است: افزودن تجهیز به کاتالوگ، خودکار مدل/مختصات ایجاد نمی‌کند؛ مدل جدید باید در چیدمان هم جانمایی شود. نام‌های اختصاصی مالک ترجمهٔ خودکار نمی‌شوند. هویت رسمی لوگوی پویشگر تأیید نشده، بنابراین نام متنی و نماد عمومی کارخانه نمایش داده می‌شود.
