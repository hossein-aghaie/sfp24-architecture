# اجرا و بررسی محیط جاری

## فایل شرکت و بارگذاری عکس — ۲۰۲۶-۱۰-۲۵

WEB برای رفع خطای عکس باید با Stop-All سپس Start-All دستی بارگذاری شود؛ در این تغییر هیچ سرویس خودکار restart نشده است. فایل جدید زیر `.local/companies/<company-uuid>/telemetry/sources/<id>/` نوشته می‌شود: `draft.enc` و `images/<hash>.png|jpeg|webp`. کتابخانهٔ جدید نیز `<company>/library/models` را استفاده می‌کند. root را با companyFilesDirectory یا COMPANY_FILES_ROOT عوض کنید؛ تغییر نام شرکت/دیوایس، مسیر را تغییر نمی‌دهد. [جزئیات انتقال و backup](guides/LOCAL-FOLDERS.fa.md).

پیش‌نویس، فایل رمزگذاری‌شدهٔ سند است و عکس binary خصوصی جدا دارد. HUB_ENCRYPTION_KEY/encryptionKeyFile قبلی حفظ می‌شود؛ فایل بدون کلید بازیابی نمی‌شود. خطای hub_invalid_secret از رمزگذاری کل سند با محدودیت توکن بود؛ رمز عبور یا کلید اتصال کاربر خراب نبود. PNG/JPEG/WebP تا۱۵۰KiB و۲۰۴۸×۲۰۴۸، با اصل بایت‌ها و alpha نگهداری می‌شود. فایل از API مجاز همان شرکت خوانده می‌شود و نباید public شود. نسخه‌های باینری قدیمی retained هستند، نه کش قابل حذف خودکار. DB و vault موجود منتقل نشده‌اند؛ مهاجرت DB لازم نیست.

مسیر قدیمی پیش‌نویس و کتابخانه برای fallback خواندن باقی است؛ تا انتقال کنترل‌شده، backup آن‌ها هم لازم است. نام/نوع منبع metadata است؛ انتخاب PLC یا حضور‌وغیاب، driver را خودکار فعال نمی‌کند. HTTP ورودی تنها مسیر فعال این ویزارد است؛ OPC UA/MQTT/خروجی‌ها همچنان اجرای آینده‌اند.


## بارگذاری ویزارد و HTTP چندکاناله — ۲۰۲۶-۱۰-۲۵

منوی ردیف ویزارد حذف پیش‌نویس را از طریق WEB انجام می‌دهد؛ پس از افزودن این قابلیت، WEB نیز باید با launcher دستی دوباره بارگذاری شود. حذف فایل از داخل برنامه tenant-scoped و با نسخهٔ CAS است؛ ذخیرهٔ معوق با نسخهٔ قدیمی نباید آن را بازسازی کند. حذف/بایگانی منبع واقعی از همان بررسی وابستگی و منطق موجود استفاده می‌کند.

برای تست این نسخه، `Stop-All.cmd` و سپس `Start-All.cmd` را دستی از ریشهٔ پروژه اجرا کنید؛ فقط رفرش UI، کد WEB و INGEST را به‌روز نمی‌کند. این تغییر مهاجرت DB ندارد و سرویس‌ها خودکار restart نشده‌اند. «نمای کلی ۳» در منوی هاب است. روش‌های غیرHTTP فقط پیش‌نویس‌اند.

مسیر قدیمی پیش‌نویس `vaultDirectory/telemetry-wizards/<company-id>/<draft-id>.enc` بود؛ نوشتن فعلی در CompanyFiles است و مسیر قدیمی فقط برای سازگاری خوانده می‌شود. همین پوشه همراه فایل encryptionKeyFile موجود باید خصوصی backup شود؛ بدون کلید رمزگذاری، فایل قابل بازیابی نیست. عکس اختیاری raster حداکثر۱۵۰KB، نمونهٔ پیام پیش‌نمایش حداکثر۲۴هزار کاراکتر و هر شرکت حداکثر۲۰۰پیش‌نویس دارد. فایل‌ها توکن اتصال مستقل ندارند؛ کلیدهای اتصال در vault قبلی‌اند. adapter فایل فعلی تنها یک فرایند WEB نویسنده را پشتیبانی می‌کند.

پروفایل جدید `http.channels.v1`: آدرس POST `/ingest/adapters/http-channels/v1/data`، هدر `Authorization: Bearer <source-key>`، JSON یا form مطابق تنظیم ویزارد. حداکثر۱MiB و۷۰۰مقدار استخراج‌شده در۱۶کانال؛ یعنی تعداد رکورد × تعداد کانال باید حداکثر۷۰۰باشد. زمان و مسیر فیلدها صریح تعریف می‌شوند، عدد رشته‌ای خودکار حدس زده نمی‌شود. code:0 تنها custody خام است؛ نتیجهٔ سطرها را در داده‌های دریافتی ببینید. قبل از اولین نمونهٔ معتبر قالب قابل تعمیر است؛ پس از آن ساختار تازه مسیر تازه می‌خواهد. مسیرهای قدیمی EdgeBox count/status بدون تغییر باقی‌اند. نشانی loopback فقط برای همان لپ‌تاپ است؛ شبکهٔ کارگاه هنوز به تأیید/تنظیم جدا نیاز دارد.

### الگوهای HTTP و تعویض کلید

HTTP عمومی از یک آدرس و Bearer مخصوص منبع استفاده می‌کند؛ حداکثر۸الگو،۱۶کانال و۷۰۰مقدار در هر بسته. الگو می‌تواند بر اساس مقدار متنی فیلد type یا وجود فیلد انتخاب شود؛ چند آرایهٔ متمایز نیز قابل استخراج‌اند. شرط‌های هم‌پوشان عمداً همگی اجرا می‌شوند؛ از کلید کانال تکراری و الگوهای ناخواستهٔ هم‌پوشان پرهیز کنید. مسیریابی متنی صریح است و نوع عدد/بولینِ داده خودکار از رشته حدس زده نمی‌شود. `$.time` یعنی زمان در ریشهٔ پیام و `[0]` یعنی ستون آرایهٔ اندیسی. JSON و فرم حامل JSON پشتیبانی‌اند؛ XML/CSV، SenML کامل، CBOR یا SOAP به این endpoint اضافه نشده‌اند.

در منبع قدیمی EdgeBox، ذخیرهٔ ساختار قابل تعریف، ورودی عمومی را فعال می‌کند و URL فرستنده باید تغییر کند. مسیرهای قدیمی برای سایر منابع هنوز برقرارند. کاربر می‌تواند کلید فعلی را ببیند یا با تأیید تعویض کند؛ تعویض فوراً قبلی را لغو می‌کند و فرستنده باید کلید جدید بگیرد. Bearer یک شیوهٔ احراز هویت است، نه رمزگذاری. [RFC6750](https://www.rfc-editor.org/rfc/rfc6750) حفاظت انتقال با TLS را لازم می‌داند؛ HTTP جاری فقط مسیر تست محلی است و HTTPS در استقرار به تنظیم واقعی سرور/پراکسی نیاز دارد. OAuth server، mTLS، Basic و انتخاب نمایشی الگوریتم رمزگذاری به این مرحله افزوده نشده‌اند.

## نگهداری کلید اتصال و نشست مرورگر — ۲۰۲۶-۱۰-۲۴

launcher جاری، مخزن رمزگذاری‌شدهٔ کلیدهای منبع را در `vaultDirectory/telemetry-keys/<company-id>/<key-id>.enc` به WEB می‌دهد؛ حساب INGEST این مخزن را لازم ندارد. رمزگذاری AES-256-GCM با `HUB_ENCRYPTION_KEY` موجود و AAD شامل شرکت/کلید است. همراه فایل‌های مخزن، فایل encryptionKeyFile موجود را خصوصی پشتیبان بگیرید؛ بدون آن نمایش کلید ممکن نیست. runtime مستقیم نیز باید HUB_ENCRYPTION_KEY را از محیط خصوصی بگیرد. متن کلید در DB، catalog یا audit ذخیره نمی‌شود و endpoint نمایش فقط برای مدیر هاب همان شرکت و مسیر فعال/نسخهٔ فعلی است. تغییر schema و مجوز DB برای این قابلیت لازم نیست. قدیمی‌های hash-only فقط با ارائهٔ نسخهٔ ذخیره‌شده و تطبیق هش ثبت می‌شوند؛ هیچ روش بازیابی حدسی وجود ندارد.

ورود پس از رفرش در همان تب باقی می‌ماند و سرور اعتبارش را کنترل می‌کند؛ sessionStorage شامل bearer نشست است، نه رمز کاربر. Logout/۴۰۱/تغییر رمز آن را پاک می‌کند. مسیرها query عمومی‌اند و مجوز مستقل نمی‌دهند. پس از بارگذاری این نسخه ممکن است یک‌بار ورود لازم باشد، چون نسخهٔ قبلی نشست را ذخیره نمی‌کرد. سپس رفرش و Back/Forward نیازی به ورود تکراری ندارند؛ انقضا/ابطال نشست همچنان معتبر است.

## گیرنده مستقل EdgeBox — ۲۰۲۶-۱۰-۲۴

کد در `services/ingest/edgebox` با پروفایل مستقل `edgebox.durable-inbox.v1` است؛ قرارداد امضاشده sfp-legacy-v1 و rc.4 عوض نشده‌اند. این دریافت محلی، اجرای کامل صنعتی rc.4 نیست. هیچ سرویس دائمی خودکار راه‌اندازی نشده است.

آماده‌سازی آفلاینِ هر شرکت با تأیید مالک:

```powershell
pnpm exec tsx tools/telemetry/provision-worker.ts --config .local/data-sources/private/state.json --company <company-uuid>
```

این دستور دو جدول inbox/rows و حساب‌های محدود tc_/ti_ می‌سازد، به WEB خواندن inbox و حذف محدود سه جدول metadata منبع خالی می‌دهد و تنظیمات خصوصی را در `.local/telemetry/private/<company-uuid>/` می‌گذارد. admin به گیرنده داده نمی‌شود. پوشه را commit نکنید. پس از تأیید صریح مالک در ۲۰۲۶-۱۰-۲۴، برای شرکت پویشگر اجرا شد؛ وجود دو جدول، خواندن با حساب محدود INGEST و WEB و انطباق شرکت بررسی شد. سرویس هنوز راه‌اندازی نشده است. پوشه خروجی موجود بازنویسی نمی‌شود.

پس از آماده‌سازی، Start-All موجود سرویس گیرنده را هم با پورت۵۲۰۸ اضافه می‌کند. برای اجرای مستقل محلی، فقط یکی از این دو روش را استفاده کنید:

```powershell
pnpm ingest:edgebox --config-dir .local/telemetry/private
```

API باید `TELEMETRY_RECEIVER_BASE_URL=http://127.0.0.1:5208` داشته باشد؛ launcher این مقدار را تعیین می‌کند. Endpointهای POST: `/ingest/adapters/edgebox-inbox/v1/count` و `/ingest/adapters/edgebox-inbox/v1/status`. هدر `Authorization: Bearer <source-key>`، نوع محتوا `application/x-www-form-urlencoded`، بدنه `node_id=101&data=[{"t":<unix_seconds>,"q":2}]` و برای وضعیت `node_id=101&data=[{"s":"off"}]`. کلید مخصوص همان منبع/شرکت و نود الزامی است. منبع قدیمی باید یک بار در تنظیمات نودش ثبت شود؛ منابع تازه EdgeBox/HTTP در زمان ساخت تنظیم می‌شوند. آدرس loopback فقط برای فرستنده همین لپ‌تاپ است؛ دسترسی شبکه کارگاه جداگانه تنظیم و تأیید می‌خواهد.

ACK پس از commit کل بسته خام صادر می‌شود؛ runner مستقل بلافاصله و سپس هر۱٫۵ثانیه پردازش را امتحان می‌کند. شروع دریافت منتظر پایان پردازش به تگ نمی‌ماند؛ ذخیرهٔ فعلی خام همچنان به DB شرکت وابسته است. دریافت بدون تگ مجاز است؛ نگاشت بعدی raw ذخیره‌شده را پردازش می‌کند. timestamp صرفاً زمان مشاهده است، نوع شمارش observed_delta و period_end خالی؛ ساعت/پوشش/بازه قطعی فرض نمی‌شود. node/time/value تکراری یک بار ثبت می‌شود؛ همان زمان با مقدار دیگر تعارض است. بدون شناسه رخداد مستقل، تشخیص دو رخداد واقعی در یک timestamp ممکن نیست. شماره نود تا پیش از اولین بستهٔ خام یا دریافت پردازش‌شده قابل اصلاح است؛ پس از دریافت قفل می‌شود. نگاشت ثبت‌شده برای حفظ معنای داده‌های قبلی تغییر نمی‌کند؛ کانال تازه منبع تازه می‌خواهد.

حد پیام شمارش۱MiB، وضعیت۶۴KiB، حداکثر۷۰۰ سطر شمارش و۵ وضعیت،۸ درخواست هم‌زمان و۱۰هزار بسته یا۱۲۸MiB ذخیرهٔ raw برای هر منبع است. وقتی ظرفیت تمام شود ACK موفق صادر نمی‌شود؛ پاک‌سازی خودکار داده نداریم. raw در دیتابیس خصوصی است، UI فقط نتایج پالایش‌شده را می‌بیند. status از تازگی ارتباط و وضعیت تولید تفکیک شده و فعلاً به تگ runtime تبدیل نمی‌شود.


حذف منبع خالی به DELETE فقط روی `telemetry_runtime_status`، `telemetry_source_configs` و `telemetry_sources` برای حساب محدود WEB نیاز دارد؛ provision آن را برای شرکت جدید و دستور آماده‌سازی INGEST برای حساب WEB موجود اعمال می‌کند. دادهٔ دریافتی یا وابستگی، مسیر را به بایگانی تبدیل می‌کند و پاک نمی‌شود. در ۲۰۲۶-۱۰-۲۴ این سه مجوز برای شرکت پویشگر اصلاح و حذف منبع مصنوعی در تراکنش برگشت‌خورده بررسی شد؛ منبع واقعی حذف نشد. برای بارگذاری سیاست جدید نود، API را با Stop-All/Start-All دستی دوباره اجرا و صفحهٔ شبیه‌ساز را تازه کنید.

## محصول جاری

فرستندهٔ خارجی تست HTTP: `external-simulator/v1/Start.cmd` و `http://127.0.0.1:5251/`؛ مستقل از Start-All و خاموش در شروع از نظر ارسال داده. نود پیش‌فرض۱۰۱؛ endpoint باید صریح وارد شود. صف در `external-simulator/v1/.local/state.json`، توکن فقط در حافظهٔ صفحه. راهنما و حدود رفتار در [راهنمای ابزار](../external-simulator/v1/README.md) است. این ابزار به‌تنهایی دریافت صنعتی هاب یا اتصال پارامتر را پیاده‌سازی/تأیید نمی‌کند.

ابتدا Check-Setup.cmd و Status-All.cmd. Start-All.cmd اجرای صریح محیط محلی موجود است؛ Stop-All.cmd فقط فرایندهای ثبت‌شدهٔ محصول را می‌بندد و MariaDB مشترک را متوقف نمی‌کند. startup عادی ممکن است provisioner درخواست‌های صف‌شدهٔ شرکت را اجرا کند؛ برای صرف بررسی، از Check استفاده کنید. bootstrap/reset یا ارتقای blanket انجام نمی‌شود.

تنظیمات و کلیدهای فعلی در .local مانده‌اند؛ مسیر vaultهای منتقل‌شده به پوشهٔ اصلی اصلاح شده است. فایل‌های MariaDB زیر .local/phase3/data و private/ دموی هاب جابه‌جا یا حذف نشده‌اند. فایل پشتیبان محلی worktreeهای قبلی در .local/archive/cleanup-2026-10-19 است و نباید push شود.

## دو برنامه، دو راه‌انداز مستقل

`Start-All.cmd`، `Status-All.cmd` و `Stop-All.cmd` در `D:/git/pouyeshgar-workshop` فقط محصول جاری را کنترل می‌کنند؛ WEB۵۲۰۶، API۵۲۰۷ و worker. CMDهای محصول، پوشه یا پورت ارائه را بررسی نمی‌کنند و به موجودبودن آن وابسته نیستند.

برای ارائهٔ فاز۲، فقط `server-control/Start.cmd`، `Status.cmd` و `Stop.cmd` در `D:/git/pouyeshgar-demo-phase2` را اجرا کنید؛ WEB۵۲۴۰ و API۵۱۸۴. هر دو برنامه می‌توانند هم‌زمان اجرا شوند؛ پورت‌ها و داده‌هایشان جداست و توقف یکی، دیگری را متوقف نمی‌کند. ارائه با JSON محلی کار می‌کند و به MariaDB محصول نیاز ندارد. هیچ حساب یا داده‌ای با این جداسازی بازسازی نشد.

ورود مستقیم شرکت پویشگر در محصول: `http://127.0.0.1:5206/company/pouyeshgar/login`. میانبر `http://127.0.0.1:5206/POUYESHGAR//login` نیز به همین ورود شرکت می‌رود و کد شرکت از URL تکمیل می‌شود؛ کاربر فقط نام کاربری و رمز را وارد می‌کند. اسلش تکراری و بزرگی حروف نرمال می‌شوند و query حفظ می‌شود؛ fragment به فرم ورود تحویل و طبق رفتار قبلی پس از خواندن از نشانی پاک می‌شود. این نشانی، صفحهٔ ارائه نیست. قبل از این اصلاح مسیر کوتاه شناخته نمی‌شد و به App نمایشیِ همین سورس می‌افتاد، نه به checkout مستقل فاز۲.

## نصب و بررسی توسعه

از ریشهٔ محصول:

~~~text
pnpm install --frozen-lockfile
pnpm test:all
pnpm build:all
~~~

نسخهٔ ابزار در packageManager/.node-version ثبت شده است؛ تنظیمات pnpm11 فقط از pnpm-workspace.yaml خوانده می‌شود. تست‌های عادی از fixtureهای موقت استفاده می‌کنند؛ تست MariaDB اختیاری به محیط ایزولهٔ صریح نیاز دارد. آن را خودکار روی دیتابیس موجود فعال نکنید.

فرمان مستقل هر بخش: pnpm test و pnpm build برای WEB، pnpm test:ingest و pnpm build:ingest برای هاب واردشده، pnpm contract:check برای قرارداد. pnpm ingest:lab یک فرمان صریح آزمایشگاهی است؛ روی پورت‌هایی که دموی مستقل هاب گرفته دوباره اجرا نشود. شبیه‌ساز به‌صورت library داخل WEB نصب نشده است؛ ساخت برنامهٔ مستقل ویندوزی برای آن در آینده با این مرز سازگار است.

## داده‌های خصوصی و انتقال به سرور

[نقشهٔ محل داده، رمزها، کلیدها و فایل شرکت](guides/LOCAL-FOLDERS.fa.md) را پیش از انتقال بخوانید. رمز ورود کاربران در DB مرکزی hash شده است؛ رمز اتصال DB و کلید هاب فایل خصوصی‌اند و مدل‌ها در کتابخانهٔ شرکت ذخیره می‌شوند. dump خودکار/بستهٔ کامل restore هنوز ساخته نشده است. با ثبت این راهنما هیچ داده یا محیط زنده‌ای جابه‌جا نشده؛ انتقال فعلی فقط با کپی سورس یا تغییر یک مسیر کامل نمی‌شود.

## فایل‌های کتابخانهٔ مدل شرکت

ورود مدل از «تعاریف شرکت ← چیدمان کارگاه ← فایل ← ورود مدل GLB» است. پس از پیش‌نمایش و تأیید نام/ابعاد متری، «ذخیره در کتابخانهٔ شرکت» فایل را مستقل از ذخیرهٔ چیدمان ثبت می‌کند. سپس در افزودن تجهیز یا ویژگی‌های آن، مدل را از «کتابخانهٔ شرکت» انتخاب و چیدمان را ذخیره کنید. فایل GLB باید بافت و buffer را در خودش داشته باشد؛ فقط مدل سادهٔ بدون decoder و بافت PNG/JPEG پشتیبانی می‌شود. برای GLB جدید نیازی به build نیست؛ برای نصب کد این قابلیت، API فعلی را با راه‌اندازهای موجود به‌صورت دستی بازراه‌اندازی و مرورگر را تازه‌سازی کنید.

فایل‌های قدیمی در `D:/git/pouyeshgar-workshop/.local/company-models/` هستند؛ نوشتن جدید در CompanyFiles است. زیرپوشهٔ هر شرکت از hash شناسهٔ داخلی آن به دست می‌آید. این پوشه را همراه دیتابیس شرکت پشتیبان بگیرید؛ JSON خروجی چیدمان شامل خود GLB نیست و به‌تنهایی پشتیبان کتابخانه محسوب نمی‌شود. فایل‌ها از API احراز‌شده خوانده می‌شوند و نباید به public منتقل شوند. پاک‌سازی کش/QA نباید این پوشه را حذف کند. در صورت قطع فرایند هنگام import و باقی‌ماندن `.import-lock`، پس از توقف API، فقط همان پوشهٔ قفل خالی را بردارید؛ GLB/JSON دادهٔ شرکت‌اند. حذف نهایی شرکت در روال فعلی DB، این فایل‌های خصوصی را هنوز خودکار پاک نمی‌کند؛ هنگام حذف نهایی باید پوشهٔ متناظر نیز توسط مسئول نگه‌داری جمع شود.

### پرامپت ساخت مدل سازگار از روی عکس

متن زیر برای سشن ابزار تولید مدل است؛ داشتن چند عکس تضمین بازسازی دقیق نیست. اگر ابزار فایل واقعی تولید نمی‌کند، باید اسکریپت قابل اجرا تحویل دهد و محدودیتش را روشن بگوید. نام mesh چراغ در این مرحله فقط برای نظم مدل است؛ چراغ‌ها به تگ یا وضعیت واقعی برنامه وصل نمی‌شوند.

```text
از عکس‌هایی که می‌فرستم یک مدل سه‌بعدی سبک و شماتیک از دستگاه برای نمایش در چیدمان کارخانه بساز. خروجی نهایی یک فایل واقعی .glb مطابق glTF 2.0 باشد، نه تصویر یا JSON چیدمان.

قبل از ساخت، نام دستگاه، عرض، طول و ارتفاع کل آن را بر حسب متر از من بپرس؛ روشن کن ارتفاع شامل ستون چراغ هست یا نه. اگر ابعاد یا نمای مهمی مشخص نیست سؤال کن و اندازهٔ واقعی را حدس نزن. شکل و رنگ‌های اصلی را از عکس‌ها بگیر؛ جزئیات ریز، پیچ‌ها و داخل دستگاه لازم نیست.

مدل را با واحد متر، محور Y رو به بالا، جلو در جهت -Z و مبدأ در مرکز کف بساز. ابعاد نهایی کل مدل، با احتساب چراغ، مطابق اندازه‌های تأییدشده باشد. مدل فقط دستگاه و متعلقاتش باشد؛ سالن، زمین، پس‌زمینه، دوربین، نور صحنه و اشیای پنهانِ اضافی نگذار.

روی بالای دستگاه یک ستون چراغ سه‌طبقه قرار بده: سبز بالا، زرد وسط، قرمز پایین. هر چراغ mesh و material جدا با نام‌های stack_light_green، stack_light_yellow و stack_light_red داشته باشد. این چراغ‌ها فعلاً ثابت و نمایشی‌اند؛ انیمیشن، چشمک‌زدن یا ادعای اتصال به وضعیت واقعی لازم نیست.

هدف حجم زیر ۵ مگابایت و حدود حداکثر ۳۰هزار مثلث باشد؛ سقف قطعی ورود ۱۲MiB است. از material سادهٔ PBR metallic-roughness و ترجیحاً رنگ ساده استفاده کن. اگر بافت لازم شد، فقط PNG/JPEG حداکثر ۲۰۴۸×۲۰۴۸ و همگی داخل بخش باینری همان GLB باشند؛ هیچ فایل یا URL خارجی و data URI استفاده نکن. از Draco، Meshopt، KTX2، skin/armature، sparse accessor و افزونه‌های glTF به‌جز KHR_materials_unlit استفاده نکن. برای چراغ، emissive معمولی کافی است؛ افزونهٔ emissive_strength نگذار. هندسهٔ Mesh با POSITION از نوع float32 و ابعاد غیرصفر در هر سه محور داشته باشد.

فایل را از نظر بازشدن، ابعاد و حجم بررسی کن و همراهش نام مدل و ابعاد کل عرض×طول×ارتفاع را بنویس. اگر محیطت امکان ساخت و تحویل GLB ندارد، صریح بگو و به‌جایش یک اسکریپت کامل Python برای Blender بده که مدل را بسازد و همین GLB سازگار را خروجی بگیرد؛ فایل ساختگی یا لینک دانلود ناموجود نده.
```
