# تصمیم‌ها و پیشنهادهای معماری

## تصمیم‌های پذیرفته‌شده توسط مالک

- نام اپ: کارگاه پویشگر؛ مخزن: hossein-aghaie/pouyeshgar-workshop، خصوصی.
- اپ مستقل از ERP؛ اتصال موردنیاز از API یا روش بین‌سرویسی که بعداً تعیین می‌شود.
- شروع از صفر و متناسب با کارگاه؛ ساختار سالن، دستگاه و نیرو قابل تغییر.
- تمام فایل‌ها و محیط‌های ایجادشده برای توسعه باید زیر D:\git\pouyeshgar-workshop باشند؛ درایو C فضای کافی ندارد.
- داده، فایل موقت و کش ابزارها تا جای ممکن در مسیرهای همین پروژه هدایت شوند. قبل از نصب ابزار یا استفاده از Docker/WSL، مسیر واقعی ذخیره‌سازی بررسی شود؛ پوشهٔ پروژه روی D به‌تنهایی تضمین نمی‌کند ایمیج یا دیسک مجازی روی C نوشته نشود.
- تغییر یا جابه‌جایی محیط‌های موجود ERP و SFP بدون درخواست مالک انجام نمی‌شود.

## پیشنهاد فعلی؛ هنوز تصمیم قطعی مالک نیست

| بخش | پیشنهاد |
|---|---|
| فرانت | Vue 3 + TypeScript + Vite |
| سه‌بعدی | Three.js، بارگذاری هنگام نیاز و مدل‌های ساده در شروع |
| بک‌اند | Node.js LTS + Fastify + TypeScript |
| دیتابیس | MariaDB/InnoDB؛ دیتابیس و کاربر مستقل |
| معماری | یک بک‌اند با بخش‌های مجزا؛ جداسازی سرویس‌ها در صورت نیاز واقعی |
| IoT | HTTP سازگار با Firmware فعلی؛ MQTT/Mosquitto در صورت نیاز |
| توسعه | لپ‌تاپ، ترجیحاً WSL پس از بررسی محل دیسک مجازی؛ پورت‌ها و دیتابیس مستقل |
| استقرار | Docker Compose و Nginx موجود روی رزبری؛ تعیین پورت و دامنه بعداً |
| تحلیل | Grafana مکمل اپ برای گزارش‌های تاریخی موردنیاز |

پیشنهاد مسیر آغاز: محیط آزمایش محلی، یک سالن قابل ویرایش، ثبت کار اپراتور، سپس دادهٔ Edge Box و استقرار آزمایشی.
پیشنهاد پیش از بهره‌برداری پایدار: SSD برای داده‌های پرتکرار و آزمون بکاپ/بازیابی.
نسخه‌ها، کتابخانهٔ UI، لایهٔ دسترسی دیتابیس، امنیت و قرارداد رویدادها هنوز انتخاب نهایی نشده‌اند.

## جهت‌گیری توسعه‌پذیری — توضیح مالک

مالک می‌خواهد ضمن تناسب با کارگاه، قابلیت دریافت داده از منابع متنوع و توسعه برای واحدهای صنعتی متفاوت در آینده حفظ شود و استانداردهای جهانی در طراحی لحاظ شوند. این جهت‌گیری هنوز الزام اجرای همهٔ مدل‌های پیوسته، خدماتی، تولیدی یا MRP در نسخهٔ اول نیست.

پیشنهاد برای بررسی: ورودی‌های جدا (فرم، HTTP، MQTT، ERP، فایل) که به قرارداد داده/رویداد نسخه‌دار نگاشت می‌شوند؛ اعتبارسنجی منبع، شناسه، زمان رخداد و دریافت، واحد، کیفیت/وضعیت داده و جلوگیری از ثبت تکراری. ذخیرهٔ خام در موارد لازم جدا از رکورد عملیاتی معتبر؛ منطق فرایند در بخش‌های مختص کاربرد.

مرجع مفهومی پیشنهادی ISA-95/IEC 62264 برای منابع و اتصال مدیریت عملیات به ERP است؛ انطباق یا گواهی استاندارد ادعا نشده و ممیزی بندبه‌بند انجام نشده است.
منابع: https://www.isa.org/standards-and-publications/isa-standards/isa-95-standard و https://reference.opcfoundation.org/specs/OPC-10030/full
