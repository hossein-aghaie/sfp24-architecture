# پویشگر — محصول جاری

Monorepo نرم‌افزار کارخانه، با WEB و INGEST مستقل. شاخهٔ توسعهٔ جاری `codex/03-production-recording` است؛ ابتدا [راهنمای مستندات](docs/START-HERE.md) و [وضعیت واقعی](docs/CURRENT-STATE.md) را بخوانید.

**مرحلهٔ جاری: ۰۳ — ثبت واقعی کار و تولید.** پایان مرحلهٔ۰۲ با تگ `stage/02-structure-and-ui-foundation` و کامیت `7d31e30` روی `codex/02-structure-audit` حفظ شده است. ابتدا کد موجود تطبیق و کمبودهای سناریوی واقعی تکمیل می‌شوند؛ نمونهٔ اپراتور هنوز backend عملیاتی ندارد. جدول مرحله‌ها در [START-HERE](docs/START-HERE.md) است. main و دموی فاز۲ تغییر نکرده‌اند.

پنل سه فضای کاری دارد: **مدیریت سامانهٔ شرکت** برای آماده‌سازی محیط و کاربران، **میز کار** برای انجام کارهای روزانه و سوابق، **نمای جامع** برای مشاهده و تحلیل چندماژولی. Company Admin مدیر نرم‌افزار شرکت است؛ پیش‌فرض فقط فضای مدیریت را می‌بیند. نمایش عملیات یا گزارش‌ها به انتخاب صریح در تنظیم فضای کاری و مجوزهای مربوط نیاز دارد؛ مدیر کارخانه بودن با مدیر سامانه بودن یکی نیست.

ورودی واحد اطلاعات پایه **تعاریف شرکت** است؛ کارت‌ها بدون دسته‌بندی واسط، مستقیم مقصد هم‌نام را باز می‌کنند. هر حساب شرکت یک کارخانه دارد: کارت **مشخصات کارخانه** نام کامل، نشانی، اطلاعات تماس و منطقهٔ زمانی را مستقل از کد ورود نگه می‌دارد؛ سالن‌ها و تجهیزات زیرمجموعهٔ همین کارخانه‌اند. رابط هاب از منوی جداگانهٔ **هاب داده ← منبع ← تگ ← تنظیمات اتصال ← داده‌های دریافتی** در دسترس است. اتصال تگ به پارامتر از **تعاریف شرکت ← تعریف داده‌ها ← پارامتر ← افزودن تگ هاب** انجام می‌شود. فرم قدیمی تنظیم منبع شمارش تولید از رابط حذف شده؛ مصرف پارامتر شمارش از «تعریف داده‌ها ← پارامتر دستگاه ← مصرف در تولید» برای بازه‌های یک‌دقیقه‌ای اضافه شده است؛ استفاده در محیط فعلی نیاز به ارتقای schema۱۷ دارد. [راهنمای جریان و حدود پیاده‌سازی](docs/guides/DATA-HUB-WORKFLOW.fa.md).

- WEB: src/ و server/
- دریافت HTTP جاری: services/ingest/edgebox و http-channels؛ lab قبلی در services/ingest/server حفظ شده و پذیرش runtime کامل rc.4 هنوز مرحلهٔ بعد است.
- قرارداد مشترک: packages/telemetry-contract/، نسخهٔ مصوب2.0.0-rc.4 بدون تغییر معنا.
- پنل آزمایشگاهی قبلی: labs/data-hub/؛ شبیه‌ساز مستقل فعلی در external-simulator/v1 و v2 است.

~~~text
pnpm install --frozen-lockfile
pnpm test:all
pnpm build:all
~~~

اجرای محیط فعلی: Check-Setup.cmd، سپس Start-All.cmd؛ [راهنمای اجرا و دو دموی مستقل](docs/RUNBOOK.md). ورود محصول محلی روی5206، دموی فاز۲ روی5240 و هاب مستقل روی5220 است. نصب یا build هیچ سرویس یا دیتابیس واقعی را خودکار راه‌اندازی نمی‌کند.

[دموی فاز۲](https://github.com/hossein-aghaie/pouyeshgar-workshop/tree/demo/phase2) در پوشهٔ مستقل D:/git/pouyeshgar-demo-phase2 حفظ شده؛ [دموی هاب](https://github.com/hossein-aghaie/pouyeshgar-industrial-platform) در پوشهٔ قبلی‌اش باقی است. آن‌ها مبنای توسعهٔ محصول جاری نیستند. صفحه‌ها، API، شبیه‌ساز و آزمون‌های مستقل دموی قدیمی از محصول حذف شده‌اند؛ اجزای بصریِ مورد استفادهٔ محصول در `src/workspace/` هستند. محصول هیچ صفحهٔ عمومی دمو ندارد و ریشه/مسیر ناشناخته به ورود شرکت می‌رود.

اسناد راهنما در docs/guides، شواهد انتقال در docs/migrations و سوابق تاریخ‌دار در docs/archive دسته‌بندی شده‌اند. فقط [نسخهٔ جاری قرارداد](packages/telemetry-contract/README.md) مرجع اجراست. history و tagهای archive امکان بازگشت دارند؛ کلید، دادهٔ محلی و عکس اختصاصی وارد Git نمی‌شوند.

| پوشه | هدف | اجرا / آدرس محلی |
|---|---|---|
| `D:/git/pouyeshgar-workshop` | محصول در حال توسعه؛ همین برنچ | `Check-Setup.cmd` سپس `Start-All.cmd`؛ WEB روی `http://127.0.0.1:5206` |
| `D:/git/pouyeshgar-demo-phase2` | دموی ارائهٔ فاز۲، با دادهٔ ساختگی و ذخیرهٔ محلی JSON | فقط `server-control/Start.cmd` در پوشهٔ دمو؛ `http://127.0.0.1:5240` |
| `D:/git/pouyeshgar-industrial-platform` | دموی مستقل هاب قدیمی، با ذخیرهٔ SQLite محلی | `Start.cmd`؛ `http://127.0.0.1:5220` |

دموی فاز۲ به MariaDB یا دریافت از تجهیزات واقعی نیاز ندارد؛ API محلی آن روی5184 برای ورود، نمودارها و ذخیرهٔ تغییرات دمو اجرا می‌شود. وابستگی‌ها در `node_modules` خود دمو نصب‌اند؛ تنظیم نصب آن از store مشترک `.local/pnpm-store` محصول استفاده می‌کند. بنابراین اکنون Start به نصب دوباره نیاز ندارد، ولی این پوشه بستهٔ قابل‌حمل مستقل برای کپی روی کامپیوتر دیگر محسوب نمی‌شود. راهنمای خود دمو در `DEMO.fa.md` آن پوشه است.

## نقشهٔ کد و فایل‌های محلی

| مسیر در همین مخزن | کاربرد |
|---|---|
| `src/` و `server/` | رابط و بک‌اند اصلی محصول |
| `services/ingest/edgebox/` و `http-channels/` | دریافت HTTP جاری |
| `services/ingest/server/` | بک‌اند آزمایشگاهی حفظ‌شده |
| `labs/data-hub/` | رابط و شبیه‌ساز هاب آزمایشگاهی |
| `packages/telemetry-contract/` | قرارداد اجرایی واحد WEB و INGEST |
| `tools/` | [راه‌انداز محلی، ابزار شبیه‌ساز و کنترل قرارداد](tools/README.md)؛ کد کمکی لازم برای CMDها و توسعه |
| `.local/` | دیتابیس و کلیدهای محلی، runtime، وابستگی‌های کش‌شده، گزارش آزمون و پشتیبان؛ خارج از Git |

شرح حجم‌ها و حدود پاک‌سازی در [راهنمای پوشه‌های محلی](docs/guides/LOCAL-FOLDERS.fa.md) آمده است. `.local` را یکجا پاک نکنید؛ داده و کلید فعال هم در آن است. حذف برنچ‌های گیت اثر قابل توجهی بر حجم دیتابیس ندارد.

## تاریخچه و مرحلهٔ بعد

[CHANGELOG.md](CHANGELOG.md) خلاصهٔ انسانی تغییرات است؛ [گزارش پاک‌سازی](docs/migrations/WORKSPACE-CLEANUP-2026-10-19.json) شواهد این مرحله و Git history جزئیات هر commit را نگه می‌دارند. `main` تاریخی، برنچ محصول و `demo/phase2` باقی‌اند؛ برنچ‌های بازنشسته با tagهای `archive/2026-10-19/*` قابل بازیابی‌اند.

مرحلهٔ جاری، بررسی و پاک‌سازی ساختار پیش از ادامهٔ ماژول «ثبت و گزارش تولید» است؛ [گزارش مرحله](docs/migrations/STRUCTURE-AUDIT-2026-10-28.json). اجرای کامل قرارداد `2.0.0-rc.4` همچنان کار جداست؛ تجمیع سورس یا موفقیت تست HTTP به معنی پذیرش runtime آن نیست. WEB و INGEST اجرای مستقل دارند.

فرستندهٔ آزمایشی مستقیم قدیمی WEB بازنشسته شده و در Start-All یا فرم اتصال وجود ندارد. شبیه‌ساز آزمایشگاهی هاب در `labs/data-hub/` باقی است؛ راهنماهای آرشیویِ فرستندهٔ قدیمی دستور اجرای جاری نیستند.
