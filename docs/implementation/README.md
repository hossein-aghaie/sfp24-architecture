# مشخصات کار برای پیاده‌سازی

این بخش دربارهٔ کاری است که قرار است یک توسعه‌دهنده، تیم یا دستیار کدنویسی انجام دهد؛ نام آن به ابزار خاصی محدود نیست. چنین سندی باید از نیاز و تصمیم به کار مشخص و قابل آزمون برسد. ایدهٔ اولیه و گفتگوی آزاد در اتاق فکر می‌مانند.

**وضعیت این پوشه:** هنوز مشخصات اجرایی تأییدشدهٔ تازه‌ای برای تغییر هسته در این مخزن ثبت نشده است. وجود راهنمای فنی یا این فهرست، مجوز تغییر کد نیست.

## بستهٔ اجرایی پیشنهادی ۵ نوامبر

[۲۰۲۶-۱۱-۰۵ — هسته، معرفی ماژول‌ها، Production + Maintenance و UI واقعی](core-module-pilot-v1/README.md) — شامل قراردادهای دقیق، Schema/API/Permission/Route، وضعیت‌های خرابی و تأیید، فایل‌های هدف Codex، کارخانه‌های ساختگی و ۵۳ آزمون پذیرش؛ **Proposed**، نیازمند تأیید جداگانهٔ معماری و اجازهٔ اجرای هر بسته. این بسته سابقهٔ طراحی پایلوت است. برای شواهد نسخهٔ اجرا به [پروندهٔ فنی کنار کد](https://github.com/hossein-aghaie/pouyeshgar-workshop/blob/627feed3f93411554be0ed0be623ec43ec1e106b/docs/development/core-module-pilot-v1/README.md) و برای تصمیم‌های باز به [نقطهٔ کنترل ادامهٔ پایلوت](../journal/2026-11-07/OPERATOR-UX-AND-MODULE-LIFECYCLE-CHECKPOINT.fa.md) رجوع کنید.

## محل ثبت کار

کار مشترک کل محصول در همین پوشه ثبت می‌شود. کار فقط مربوط به یک ماژول در پوشهٔ اجرایی همان ماژول است و از راهنما و سوابق آن لینک می‌گیرد. کار اختصاصی هسته از [راهنمای هسته](../core/README.md) و [سوابق هسته](../core/RECORDS.md) پیدا می‌شود. [قواعد محل ثبت](../governance/DOCUMENTATION-POLICY.md).

## یک کار آمادهٔ تحویل چه باید داشته باشد؟

هدف و محدوده، تصمیم و قواعد ارتباطی مبنا، وضعیت و نسخهٔ کد، ورودی و خروجی، تغییرات داده و رابط، مجوز و جداسازی شرکت‌ها، وابستگی‌ها، معیار پذیرش، آزمون و روش بازگشت باید معلوم باشند. اگر چیزی تصمیم نشده، صریحاً ثبت شود و اجرا به‌جای تصمیم‌گیری پنهان استفاده نشود. [روش درخواست و تأیید](../governance/CHANGE-WORKFLOW.md).

## راهنمای فنی موجود

[راهنمای توسعهٔ نسخهٔ موجود](DEVELOPER-GUIDE.fa.md) مسیر بررسی کد را توضیح می‌دهد و [وضعیت محصول](../STATUS.fa.md) محدودیت ادعاهای فعلی را نشان می‌دهد. این‌ها با تسک اجرایی تازه تفاوت دارند. برای دستور کار دستیارهای هوش مصنوعی به [قواعد مخزن](../../AGENTS.md) رجوع کنید.

## چه چیزی کنار شاخهٔ کد می‌ماند؟

[قاعدهٔ تفکیک کد و اسناد](../governance/CODE-AND-DOCS.fa.md) حداقل نوشته‌های مخزن کد، برنامهٔ کار در جریان، گزارش آزمون و روش انتقال نتیجهٔ ماندگار به این مخزن را توضیح می‌دهد. فهرست تسک‌های روزمره لازم نیست در دو جا هم‌زمان کپی شود.
