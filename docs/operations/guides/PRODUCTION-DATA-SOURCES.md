# منابع اطلاعات تولید — راهنمای همین نسخه

> نسخهٔ راهنمای موضوعی؛ کد مبنا b3f203b، بازبینی انتقال ۲۰۲۶-۱۱-۰۲. متن اولیه در [کاتالوگ منابع](../../sources/CATALOG.md) محفوظ است. دستورها برای مخزن محصول و محیط مشخص همان نسخه‌اند؛ خود مخزن اسناد اجرا نمی‌شود.


این قابلیت در همان نرم‌افزار و رابط فاز دوم است؛ یک نرم‌افزار یا اکانت جدا نیست. نام صفحهٔ مدیریتی «منابع اطلاعات تولید» است. هدف فعلی فقط تأمین **تعداد قطعات پردازش‌شده در هر دقیقه** برای گردش «ثبت و گزارش تولید» است. برنامه‌ریزی، OEE و استنباط توقف یا سرعت ماشین در این توسعه ساخته نشده‌اند.

## روال کار مدیر شرکت

۱. در «منابع اطلاعات تولید»، **افزودن منبع** را بزنید و یکی را انتخاب کنید:

| انتخاب | چه کسی اطلاعات را می‌آورد؟ | وضعیت پیاده‌سازی |
|---|---|---|
| ارسال از دستگاه | EdgeBox یا نرم‌افزار دیگر، HTTP POST می‌فرستد | گیرنده، کلید اختصاصی، رسید پس از ذخیره و حذف شمارش تکراری عملیاتی آزمایشی است |
| خواندن از API | سرور ما به نشانی REST تأییدشده درخواست می‌فرستد | دریافت دستی و زمان‌بندی‌شده، Bearer رمزگذاری‌شده و نگاشت فیلدهای JSON ساخته شده |
| فایل Excel یا CSV | مدیر فایل را انتخاب می‌کند | خواندن XLSX واقعی و CSV، انتخاب ستون، بررسی ردیف‌ها، پیش‌نمایش و تأیید ساخته شده |

۲. نامی ملموس مانند «شمارندهٔ تراش شمارهٔ ۱»، دستگاه مرتبط و آزمایشی/واقعی‌بودن اطلاعات را مشخص کنید. برای HTTP، پنجرهٔ «آدرس و کلید اتصال» آدرس دریافت، شناسه و کلید پوشیدهٔ قابل کپی و فایل مشخصات را می‌دهد. کلید قبلی قابل بازیابی نیست؛ ساخت کلید تازه، قبلی را باطل می‌کند. شبیه‌ساز مستقل اکنون پنجرهٔ سادهٔ تنظیم، بررسی واقعی اتصال، شروع/توقف و صف آفلاین دارد؛ [راهنمای قدم‌به‌قدم](DEVICE-CONNECTION-QUICKSTART.md).

۳. در **اطلاعات دریافتی**، پوشش و تعداد را بررسی کنید. پیش‌فرض، آخرین اطلاعات ذخیره‌شده است؛ «امروز» و بازهٔ دلخواه نیز واقعاً دادهٔ API را عوض می‌کنند. نبود اطلاعات با تولید صفر فرق دارد. مغایرت از جمع کنار گذاشته می‌شود. آگاهی از دریافت تازه، به معنای وضعیت روشن/خاموش دستگاه نیست.

۴. در **استفاده در گزارش تولید**، «استفاده برای تعداد تولید» را فعال کنید. فقط همین ورودی مشخص وصل می‌شود؛ مدیر فرم را برنامه‌نویسی نمی‌کند. تغییر دستگاه از زمان مشخص انجام می‌شود و تاریخچهٔ قبلی جابه‌جا نمی‌شود. توقف استفاده یا غیرفعال‌کردن منبع، داده را پاک نمی‌کند.

API بیرونی باید در تنظیمات امن سرور مجاز شده باشد؛ مدیر شرکت نمی‌تواند هر نشانی دلخواه شبکه یا دیتابیس را فراخوانی کند. فرم در نبود این تنظیمات، صریحاً علت را می‌گوید.

## روال اپراتور

اپراتور همان فرم ثبت تولید در کار روزانه یا کارخانه را دارد؛ دسترسی مدیریتی منابع لازم ندارد. دستگاه، قطعه/نام موقت، عملیات در صورت نیاز و **بازهٔ واقعی کار** را مشخص می‌کند. اگر منبعی تنظیم نشده، شمارش دستی قبلی حفظ می‌شود.

اگر منبع فعال و تمام دقیقه‌های بازه معتبر باشد، تعداد آن بازه از سرور خوانده می‌شود. برای مثال با **۱۲۳ پردازش‌شده و ۳ ضایعات، ۱۲۰ سالم** محاسبه می‌شود؛ اپراتور همان تعداد منبع را دوباره تایپ نمی‌کند. این محاسبه در سرور هم کنترل می‌شود. قطعه و OP از پیام شمارنده حدس زده نمی‌شوند؛ انتخاب اپراتور، ادعای گزارش است و در شواهد ذخیره می‌شود.

اگر اطلاعات ناقص یا دارای مغایرت باشد، ثبت نهاییِ متصل رد می‌شود. جایگزینی با تعداد دستی فقط با مجوز مستقل `production.override_source` و دلیل ثبت‌شده مجاز است. مجوز مدیریت کاربران به‌تنهایی نباید مجوزهای عملیاتی را دور بزند.

پیش‌نویس قابل ادامه است؛ نهایی‌شدن، نسخهٔ شمارش و منشأ آن را ثابت می‌کند. دریافت دیرهنگام گزارش نهایی را بازنویسی نمی‌کند. اصلاح ضایعات با مجوز و دلیل، شمارش ثابت قبلی را نگه می‌دارد. یک دقیقهٔ دستگاه نمی‌تواند در دو گزارش نهاییِ متصل مصرف شود، حتی با عوض‌کردن منبع. گزارش دستی مستقل با شمارش خام جمع نمی‌شود. دادهٔ SIMULATOR در گزارش مشخص است و در خلاصه‌ها از گروه‌های واقعی/دستی جدا می‌ماند.

## قرارداد دقیق و محدودیت‌ها

- زمان، شروع یک دقیقهٔ کامل با `Z` یا اختلاف منطقهٔ زمانی است؛ تعداد، عدد صحیح نامنفی همان دقیقه است. شمارندهٔ تجمعی یا پالس نامشخص را خودکار تبدیل نمی‌کنیم. فرمول دادهٔ سالم فقط وقتی معتبر است که این ورودی واقعاً کل قطعات پردازش‌شده را بشمارد.
- HTTP همان قرارداد نسخهٔ ۱ و `Authorization: EdgeKey ...` را حفظ می‌کند؛ جفت‌های `time/qty`، `t/q` و `T/Q` پذیرفته می‌شوند. نگاشت فیلد JSON برای فرمت دیگر باید صریح باشد. حداکثر بسته ۱۴۴۰ نمونه/۲۵۶ کیلوبایت، تأخیر عادی قابل تنظیم ۱ تا ۳۰ روز است. مسیر تاریخی Replay فقط برای SIMULATOR است.
- REST فعلاً **GET JSON با from/to برای ۲۴ ساعت گذشته** است؛ حداکثر ۱۴۴۰ نمونه/۲۵۶ کیلوبایت، timeout هشت ثانیه، بدون Redirect. بازخوانی پنجره، دیررس‌ها را می‌گیرد و تکرارها دوباره شمرده نمی‌شوند؛ بازیابی خودکار قطعی بیش از ۲۴ ساعت برای REST ساخته نشده است. خطا و موعد تلاش بعدی ذخیره می‌شوند. زمان‌بندی هر ۶۰ تا ۳۶۰۰ ثانیه با حلقهٔ بررسی ده‌ثانیه‌ای است؛ SLA دقیق زمان واقعی نداریم.
- CSV حداکثر ۵۰۰ ردیف داده و ۳۰ ستون دارد؛ XLSX حداکثر ۲ مگابایت فشرده، یک برگه، بدون فرمول/ماکرو/لینک خارجی و بدون تاریخ عددی Excel است. زمان باید متن دارای منطقهٔ زمانی باشد. ستون‌های فایل از نمونه بررسی می‌شوند. پیش‌نمایش ۱۵ دقیقه اعتبار دارد؛ تأیید دوباره همان رسید را برمی‌گرداند. ردیف تکراری در خود فایل باید اصلاح شود. همهٔ این‌ها برای **ورود شمارش دقیقه‌ای** است؛ واردکردن فایل کامل گزارش کار یا فایل دلخواه ERP ساخته نشده.
- بازهٔ بررسی حداکثر هفت روز است؛ جدول حداکثر ۱۰۰۰ ردیف نشان می‌دهد ولی جمع کل بازه را حساب می‌کند. بازه‌های منبع نباید وسط گزارش عوض شوند. تقسیم یک شمارش بین چند OP هم‌زمان یا حل خودکار مغایرت ساخته نشده است.
- API اسکادا/ERP فقط در صورت انطباق با قرارداد همین REST/HTTP قابل استفاده است. MQTT، OPC UA، RFID، دوربین، اتصال مستقیم دیتابیس و قالب‌های اختصاصی این محصولات **پیاده نشده‌اند**. OEE، زمان کار، توقف و افت سرعت از صفر/کمبود شمارش استنباط نمی‌شود.
- ذخیره‌سازی پایدار و آزمون MariaDB واقعی داریم؛ هیچ Firmware واقعی یا سرویس مشتری آزمایش نشده. HTTPS و سیاست نصب واقعی/پشتیبان‌گیری/نگه‌داری داده باید پیش از بهره‌برداری بررسی شوند. پاک‌سازی دوره‌ای داده و پیش‌نمایش‌های منقضی، ابزار حل تعارض و UI بازگردانی نسخهٔ تنظیمات هنوز ساخته نشده‌اند.

## راهنمای توسعه‌دهنده

| محل | مسئولیت |
|---|---|
| `server/data-hub/adapters.ts` | قرارداد انتقال HTTP/REST/فایل، مسیر فیلدها، محدودیت فایل، Origin مجاز و رمزگذاری کلید REST |
| `server/data-hub/normalize.ts` | معنای شمارش دقیقه‌ای، اعتبار زمان/تعداد و بازه |
| `server/data-hub/service.ts` | رسید/دادهٔ خام/نمونهٔ استاندارد، تکرار و مغایرت، انتساب تجهیز و پیکربندی نسخه‌دار |
| `server/data-hub/production-source.ts` | مصرف شمارش معتبر برای تجهیز و بازه، مستقل از رابط کاربر |
| `server/operations/production/service.ts` | مالک گزارش کار، ضایعات، تأیید، اصلاح، Snapshot و قفل مصرف دقیقه‌ها |
| `src/data-hub/SourceWizard.vue`, `SourceFiles.vue`, `DataHubWorkspace.vue` | انتخاب روش، بررسی فایل و صفحهٔ سادهٔ مدیر |
| `src/company/ProductionSourceInput.vue` | همان ورودی تولید اپراتور، با شمارش دستی یا متصل |

Modular Monolith حفظ شده است. حساب/مجوز/دیتابیس شرکت در هستهٔ موجود می‌ماند؛ آداپتر نباید مستقیم جدول گزارش تولید را تغییر دهد. برای افزودن منبع، انتقال/نگاشت را به مشاهدهٔ استاندارد تبدیل کنید و آزمون جداسازی/تکرار/دیررس اضافه کنید. برای افزودن معنای جدید مثل وضعیت ماشین، قرارداد نوع/واحد/زمان/تجمیع و مصرف‌کنندهٔ مستقل لازم است؛ فقط اضافه‌کردن نام به فهرست، پیاده‌سازی محسوب نمی‌شود.

Migration شرکتی ۷ افزایشی است؛ نسخه‌های ۱ تا ۶ تغییر نکرده‌اند. تنظیمات منابع قدیمی HTTP هنگام Migration مقدار اولیه می‌گیرند. جدول‌های جدید: `hub_source_settings`, `hub_source_revisions`, `hub_import_previews`, `hub_count_previews`, `hub_report_count_evidence`, `hub_count_claims`؛ دو ستون مرجع شمارش/دلیل جایگزینی به `production_lines` اضافه شده‌اند. شواهد و تاریخچه INSERT/SELECT هستند؛ دادهٔ جاری Preview/Claim قابل تغییر است. ساخت یا ارتقای دیتابیس مالک به‌صورت خودکار در سرور وب انجام نمی‌شود.

تنظیمات سرور: `HUB_ALLOWED_API_ORIGINS` فهرست Originهای تأییدشده و `HUB_ENCRYPTION_KEY` کلید تصادفی ۶۴ نویسهٔ هگز، خارج Git. این کلید باید پایدار/محافظت‌شده باشد؛ عوض‌کردن بی‌برنامهٔ آن، کلیدهای REST قبلی را ناخوانا می‌کند. درخواست‌های واقعی بیرونی نیازمند تأیید و تنظیمات نصب هستند؛ آزمون فعلی فقط localhost است.

APIهای جدید زیر `/api/v1/company`:

- `PUT /data-hub/connections/:id/source`: تنظیم قالب/API/فاصله و نام/فعال‌بودن به‌صورت اتمیک و با نسخه.
- `POST /data-hub/connections/:id/fetch`: دریافت از API مجاز.
- `POST /data-hub/connections/:id/files/inspect`, `/preview`, `/confirm`: ورود فایل مرحله‌ای و شرکت/کاربرمحور.
- `POST /production/count-source`: بررسی منبع و صدور Preview برای کاربر مجاز تولید، بدون الزام دسترسی مدیریت Hub.

API قدیمی فقط‌خواندنی `GET /data-hub/production-count` برای سازگاری مانده است. گزارش واقعی از سرویس تولید، `countEvidenceId` و بررسی مجدد سمت سرور استفاده می‌کند.
