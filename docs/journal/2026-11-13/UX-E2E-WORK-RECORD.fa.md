# سابقهٔ اجرای UX یکپارچه در شاخهٔ کد

تاریخ: ۲۰۲۶-۱۱-۱۳. نوع: مدخل کار اجرایی و خلاصهٔ دستور واقعی مالک؛ Transcript گفتگوهای پیشین نیست. وضعیت: In progress؛ جزئیات طراحی Proposed و اجرای مرحله‌ای مجاز است. این سابقه تأیید نهایی UX، Quality 0.1، X200 یا قرارداد جدید نیست.

مالک پس از مشاهدهٔ نمونهٔ مستقل بازبین، اجرای مسیر واقعی Developer Admin → Company Admin → Workspace/Desk → اپراتور/بازبین را با API موجود و Fixture ایزوله مجاز کرد. ساخت شاخه و Checkpoint و Push همین کار مجاز است؛ main، Merge، Deploy، Release، Backend و مدل مجوز یا Schema تازه خارج از اختیارند. هدف جابه‌جایی صرف رنگ‌ها یا HTML مستقل تازه نیست.

اصل گزارش فنی، متن دریافتی و شواهد طبق [تفکیک کد و اسناد](../../governance/CODE-AND-DOCS.fa.md) در مخزن کد نگه داشته می‌شوند:

- [پروندهٔ جاری کار](https://github.com/hossein-aghaie/pouyeshgar-workshop/tree/codex/ux-e2e-2026-11-13/docs/development/ux-e2e-2026-11-13).

مبنای خوانده‌شدهٔ اسناد 33b16cb556a8c59a605428a959c130bb22973e66 است. STATUS و Workspace آن دربارهٔ نسخهٔ قدیمی کد هستند؛ آن‌ها را نبود Quality جدید یا تأیید قرارداد عمومی تلقی نمی‌کنیم. برای وضعیت واقعی نسخه و Code SHA آزموده‌شده به پروندهٔ کد مراجعه شود. نسخهٔ دوم گزارش اجرایی در این مخزن ساخته نمی‌شود.

محدودیت کشف‌شده: History فعلی Quality فقط تا ۱۰۰ رکورد مجاز برمی‌گرداند و Count/Pagination ندارد. UI می‌تواند موارد دریافتی را دسته‌بندی کند، ولی صف جامع یا شمار کل نباید ادعا شود. تغییر API در این مأموریت مجاز نیست؛ این نکته یک محدودیت اجرایی گزارش‌شده است، نه تصمیم معماری جدید.

پذیرش نمونه توسط مالک نهایی نبوده است. نقد بعدی همکار: منتظر دریافت. پس از شواهد Runtime، لینک ثابت نسخهٔ گزارش از همین مدخل معرفی می‌شود؛ اسناد عمومی main به‌عنوان نسخهٔ عملیاتی تازه بازنویسی نمی‌شوند.
